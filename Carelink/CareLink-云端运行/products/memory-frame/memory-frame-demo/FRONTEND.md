# 双端前端交付

文件范围：`server/public/index.html`、`style.css`、`app.js`，沿用已有 `assets`，不改后端协议。

入口：`/family` 手机家人端、`/frame` 相框端。会话分别保存在当前浏览器 localStorage；邀请通过 fragment 读取并立即从地址清除。二维码由同源 `/qr.svg` 生成。首次家庭创建需部署者提供开通码。

已实现：创建、加入、家人邀请和相框配对；JPEG 压缩上传；照片/文字/真实来源空间链接；getUserMedia 采样、PCM16 WAV 16kHz 单声道转换、60 秒截断、试听及上传；录音开始固定照片 parent；独立音频播放不受轮询 DOM 更新影响；双向轮询和离线退避；照片前后切换；相框送达及播放回执；记忆详情、原转写与人工修订、AI 重试、待确认标识；人物维护、人物/年份筛选；设备在线状态及 owner 移除；IndexedDB 保存媒体 Blob、文本、固定 parent、稳定 send UUID 与已上传文件 ID，实现重开恢复及失败重试。

本地验证：Node 语法检查通过；独立 headless Chrome 两个隔离上下文，手机 390×844、相框 1280×900。通过创建家庭、照片压缩上传、页面重载草稿恢复、fragment 配对、录音跨越 3 秒轮询、WAV 后端校验上传、回信同步、记忆修改、时间筛选、无横向溢出检查；无 pageerror。录音自动化使用 Chromium 假麦克风测试输入，**未验证真人周围音频采集**。实际录音需用户主动点击并授予麦克风权限，手机跨设备访问需要 HTTPS。

外部限制：此 worktree 未接 CloudBase、ASR 和模型服务；本地真实显示 AI 未配置失败，原声仍可保存与播放。没有 TTS、虚构转写、假在线、假空间重建或预置家庭故事。二维码/分享链接在 localhost 仅用于本机验证，跨网需总控部署的公网域名。

运行：使用 COORDINATION.md 的 Node 路径，`PORT=8792 node server/server.js`（从 memory-frame-demo 目录）。测试依赖安装期间 pnpm 报 core-js-pure 构建脚本未批准，包已安装且服务/前端验证均运行正常。

## 云端签名地址与会话恢复修复

签名音频地址更新时，当前正在播放的音频流保持不变；暂停、再次播放、播放结束或明确加载失败后采用 state 中最新地址。家人端当前音频、相框播放器和详情播放器共用此策略，切换照片会停止旧照片原声。401 停止自动轮询，提示会话失效并提供重新加入/配对入口；IndexedDB 草稿仍按原家庭保留，加入相同家庭后恢复。损坏的 localStorage 会话 JSON 安全回到加入页。

专项浏览器验证使用同源拦截的不同签名 URL 和合成 WAV 播放输入，验证双端播放中不换源、暂停/再播换源、加载失败换源、照片切换、401 停止轮询（含 online 事件）、重新加入恢复草稿、损坏 JSON 恢复；未调用真实云端签名服务，未采集真人音频。

## CloudBase 测试域名邀请兼容

公网验收发现首次访问 CloudBase 测试提示页会丢失 fragment，而 query 可以保留。仅 hostname 以 `.service.tcloudbase.com` 结尾时，分享和二维码使用 `?invite=`；其他域名继续使用 `#invite=`。前端两种形式均读取并立即从地址清除，表单支持完整链接或纯邀请码；邀请区提供可选取邀请码和“复制邀请码”。这是测试域名上 24 小时临时邀请能力码的兼容取舍，网关可能记录 query；不用于永久会话凭据。index.html 的脚本版本更新为 `app.js?v=0.1.1`，避免已打开过的浏览器继续使用旧解析逻辑。

已在全新公网相框浏览器验证平台提示页保留非敏感 query 探针；本地隔离浏览器验证 query/fragment 读取与清理、域名分流、二维码链接、复制邀请码入口及三种 join 输入。修复部署后需再次用全新上下文确认真实邀请自动填充。
