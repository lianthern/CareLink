## 使用行为

驻足只触发邀请。邀请明确说明：“确认后，AI 会读取这张照片，先温和地问您一句。不会自动打开麦克风。”老人选择“和 AI 聊聊”后，受控入口 `MemoryAI.openFromPresence(messageId)` 打开对话，检查现有 `aiCapabilities`，再使用现有 `aiChat` 读取**邀请显示时固定的照片**，最多发起一次首问请求。后台收到新照片或相框当前展示切换，不会换掉这次确认的照片。

首问**先显示文字**。没有自动朗读、麦克风申请、录音、TRTC 实时语音或联系操作。朗读仍需老人点击“朗读回复”；输入、语音转写和实时语音仍使用原有显式入口。普通 `MemoryAI.open()` 与 `MemoryAI.open(messageId)` 保持手动行为，打开时不会自行调用 `aiChat` 或勾选读取照片。

驻足入口已经固定照片，因此默认折叠“添加家庭照片”选择器，保留独立的已选缩略图、标题和读图复选项，仍可点摘要展开调整。普通 `MemoryAI.open(messageId)` 继续默认展开照片选择器。只调整初始折叠状态，不更改照片固定、读取授权或聊天布局。

首问提示要求只问一句简短、温和、开放式的问题，依据可明确看见的细节，不猜人物身份、亲属关系、地点、时间、情绪或照片背景；看不清时使用不预设事实的问题。前端只接受 `imageUsed:true` 且长度不超过 160 字的单一问句，其他回复回退普通聊天。提示与问句形状检查不能保证真实模型始终准确；本次没有把 provider 替身的输出当作模型视觉质量证据。

读取不可用、能力检查失败、模型失败、未实际读图或返回不适合的开场内容时，界面说明已保留普通对话，取消读取勾选，不自动重试。能力检查仍可由老人手动重试；重试不会再次自动发起首问。模型的操作建议不会在首问中生成确认卡片或执行操作。

## 取消与兼容边界

- 首问的能力检查和模型结果都绑定原对话对象、打开代际、会话 token、家庭、照片 ID 与 `image` 身份。返回前再次检查有效会话、页面可见、照片仍存在和忙碌状态。
- 关闭、停止、清空、切后台、切换实时语音或家人通话暂停会取消首问。state 更新删除或替换原照片会立即取消；快速关闭后重开相同照片，旧响应也不能触发请求或覆盖新草稿/对话。
- AI 请求已经发出后再取消，会中止浏览器等待并忽略迟到结果；不能承诺撤回供应商已经接收的计算。能力检查期间取消则不会发出首问请求。
- 首问等待期间禁用发送、录音和换图控件，保留停止和关闭入口。收到问题后恢复普通对话；前端历史存储完整的 user/assistant 一对，后续手动回答符合现有服务端偶数历史配对要求。内部自动种子通过 WeakSet 对象身份标记，仅在展示时隐藏，因此界面直接显示 AI 首问，不虚构老人发言；老人手动输入完全相同的文字仍正常显示。标记不加入 API 数据。
- 现有驻足事件 RTT 保守期限、持久水位去重、先消费再门禁、拒绝、不排队和撤销策略均保留。照片固定不代表推断老人正在注视照片。
- 不改 API、Windows 设备端、版本号、3D 或 TRTC 主逻辑，也没有部署或公开仓库写入。
