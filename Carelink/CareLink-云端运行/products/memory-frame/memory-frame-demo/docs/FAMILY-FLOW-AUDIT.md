## 基线实际方法和结果（历史，未替代上述最终检查）

使用 Node 24.19.0、Chrome 153.0.8010.49、Playwright，三个独立浏览器 context 分别作为创建者、家人、相框。使用真实 `createApp()` HTTP 服务、随机本机端口及显式 `new LocalStore(mkdtemp(...))`，从空数据开始；没有读 `.data`、私有快照或部署配置。没有替换业务 `/api`，也没有预注入登录会话。

测试照片由浏览器 canvas 生成；录音使用 Chrome `--use-fake-device-for-media-stream` 合成输入，经实际录音、重采样、WAV 上传链路。ASR、整理、AI 回答用显式 adapter 替身；实时 provider 显式关闭。所有浏览器外部网络请求均阻断，实际记录为零。业务请求中的密码、会话、邀请、令牌和媒体地址不写入报告。

## 可复现的体验问题与建议

已解决两项，另有两项非阻塞体验建议；本任务未修改业务代码。

1. **已解决：基线 3D 入口词义偏宽。** 原“粘贴影石分享链接”现已改为“粘贴影石时光舱分享链接或文字”，帮助区明确是已生成作品的“网页链接分享”，普通视频/特效视频不能直接变为空间；最终实际 HTTP+Chrome 已验证视频提示和分享文字导入路径。
2. **已解决：首问代发内容显示成“你”。** 基线阶段从作者截图发现此问题并报主任务；最终整合已隐藏自动 seed，内部对话配对保留。实际 HTTP+Chrome 验证只显示 AI 首问，用户手工输入恰好相同文字仍正常显示。
3. **相框横屏文字框需要发现可滚动。** 1180×820 下照片右上文字框的发送者/时间行部分落在滚动区下方；正文及听/说按钮可用，820×1180 可完整看到该行。可增加滚动提示，或弱化时间行占高。不是内容丢失。
4. **老人 AI 页信息较多，横屏发送在首屏下方。** 最终 1180×820 首问截图中，照片选择和能力检查占据上部，输入框在弹窗下沿，发送需要在弹层内下滑。实际 Playwright 可滚动并回答成功，820×1180 可看到输入和发送；因此列为非阻塞的可发现性问题。建议把首问与“回答”放在首屏、默认收起已选择照片的添加区。说明已提示横屏向下滑；没有真人老人实机证据，不宣称已通过老人可用性验收。
