# 影石 3DGS 后续接入：迁移后的下一项工作

2026-09-23，只读调查记录。用户要求先换到 Windows 接手，再实施；本次没有改动或部署任何3D功能。

## 直接观察到的事实

- 分享页面 HTTP 200，标题 `September 22's Spatial Capture`，相机标记 `X5`；页面显示 Insta360 / Remy 来源。
- 页面 `__NEXT_DATA__` 的 `props.pageProps.taskDetail.outputs` 包含 `type=model` 的 `.sog`、`.json`、`.zip`，另有两个视频输出。页面路由为 `/3dgs/remy`。
- `.sog` 的资源地址来自 `insta360-app-hz.oss-cn-hangzhou.aliyuncs.com`，带 OSS 签名参数；本次返回的有效时长参数为604799秒，约7天。不能把这条签名地址当永久链接。
- 对页面给出的原始签名地址，HEAD失败；使用 GET + `Range: bytes=0-127` 成功，HTTP206，`Content-Range: bytes 0-127/16324085`，只读取128字节。文件约16.3MB，开头 `50 4b 03 04`，与ZIP容器一致。HEAD失败不代表GET不可用，签名可能限定方法。
- 没有完整下载、校验全部内容、解压、转换或用自有渲染器打开模型。未证明相机初始位姿、碰撞或手机性能兼容。
- 页面响应含 `X-Frame-Options: ALLOW-FROM https://*.insta360.com`。这是旧式指令，各浏览器行为不同；不能据此认定可跨站嵌入，也不能只凭这条就断言所有浏览器都会阻止。iframe能否用需要实测。
- 原始签名URL没有写入仓库或接手文档。导入时从用户的分享链接重新解析，不保存已过期签名为长期资源。

## 能得出的结论

“用户粘贴影石分享链接 → 后台读取该场景模型 → 保存到本项目 → 两端观看”有实际技术依据，且不需要重新训练。当前验证到的是模型资源确实可读取，完整导入与渲染尚未验收。

影石[官方说明](https://onlinemanual.insta360.com/app/zh-cn/operation_tutorial/edit_function/3dgs)支持网页分享，但目前写明暂不支持源文件下载或离线导出。因此这里发现的是网页交付的模型资源，不是已承诺长期兼容的官方导出API。后续要保留来源信息，并考虑页面结构或分享权限变化时的失败提示与原链接兜底。

PlayCanvas有公开的 [SOG格式文档](https://developer.playcanvas.com/user-manual/gaussian-splatting/formats/sog/)；可优先验证兼容该格式的渲染路线。文件扩展名和ZIP头不足以单独证明本样例完全符合文档，必须检查模型元数据后再选库。

## 下一步建议与验收

1. 在迁移完成后的开发环境，对同一个样例做限额完整下载与文件结构检查；验证SOG版本、元数据、纹理、初始相机及需要的辅助JSON，保留来源标识。
2. 用独立验证页打开模型，实测Windows桌面及手机浏览器的加载、旋转、移动、复位和内存占用。先实现基本观看，不承诺复制影石全部漫游与碰撞效果。
3. 后端增加独立的模型导入任务：保存原分享链接、场景ID、状态、资源校验值和本项目私有存储ID；异步处理、有明确进度、可重试且去重。不改动原声/照片收发的可用性。
4. 输入仅接受允许的影石分享域名；资源下载仅接受实际核实的HTTPS资源域名，每次重定向与解析结果重新校验，拒绝本地/内网地址，限制下载大小、耗时与解压体积。不要做任意URL代理。
5. 模型约16.3MB，不能走现有3MB照片/录音base64上传。需要独立的流式下载/云存储路径；默认只按用户实际打开加载模型，避免每次轮询和消息卡片列表重复下载。
6. 前端保持“粘贴影石链接”简洁入口，显示导入中/可观看/导入失败；可观看时在两端打开自有查看器，失败时可打开原链接。不能将打开影石网页冒充自有3D查看器。
7. 验证邀请家庭隔离、过期模型URL刷新、重复导入、撤销分享/失效链接、大文件限制、低性能手机和返回照片页后的资源释放。

先实现影石已生成场景的导入与观看，不购买GPU，不建立自训练管线。是否支持 `.ply`、`.splat`、`.spz` 等额外上传格式应在用户确有文件需求后再扩展。
