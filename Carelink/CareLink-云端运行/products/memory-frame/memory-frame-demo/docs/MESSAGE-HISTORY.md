# 完整记忆历史协议

本协议扩展现有 `POST /api`，继续使用 `Authorization: Bearer <session>`。`owner`、`family`、`frame` 都可读取本家庭历史；每次请求先检查会话有效期、退出/撤销状态和账号成员资格。分页游标不能代替登录。

## 最近窗口与历史刷新

`state` 不带新参数时，`messages` 仍只含最近 **150** 条未删除消息，按 `(createdAt, _id)` 升序返回。已有字段保持兼容，新增：

```json
{
  "messagePage": {
    "nextCursor": "opaque-cursor-or-null",
    "hasMore": true,
    "total": 238
  }
}
```

`total` 包含该家庭所有未软删除消息，包括照片/文字/空间记忆和相框回复，不能直接当作照片数量。`hasMore` 表示还有比本批最旧消息更早的记录；没有更多时 `nextCursor` 为 `null`。空家庭返回 `total: 0`、`hasMore: false`、`nextCursor: null`。

已加载较早记录的客户端可请求：

```json
{
  "action": "state",
  "data": { "historyIds": ["previously-loaded-message-id"] }
}
```

提供 `historyIds` 时，响应额外包含 `historyMessages`；该字段是所请求 ID 中**仍属于本家庭、未删除、且不在当前最近 150 条中的消息**。它与 `messages` 使用相同的媒体地址和空间状态生成逻辑，反映人工修订、AI 状态、空间状态及照片/原声地址刷新。媒体缓存仍沿用既有 10 分钟刷新、15 分钟有效期策略。

`historyIds` 必须是至多 300 个字符串组成的数组，每个 ID 匹配 `[A-Za-z0-9_-]{1,160}`。空数组有效，重复项去重；其他类型、非法 ID 或超量返回 HTTP 400。语法合法但不存在、已删除、属于其他家庭或其他记录类型的 ID 均不返回。查询从本家庭消息列表取交集，不逐 ID 裸读。未提供此参数时不返回 `historyMessages`。

客户端每轮以 `messages + historyMessages` 替换本轮请求所覆盖的已载入记录，按 ID 去重；请求中已有而响应两处都没有的记录应移除。需包含上一轮最近窗口内已载入的 ID，以保留新消息把它们挤出最近窗口后的记录。异步响应应检查家庭/账号和请求版本，防止切换家庭、退出或并行翻页后旧响应覆盖新状态。

## 向前翻页

```json
{
  "action": "history",
  "data": { "cursor": "state.messagePage.nextCursor", "limit": 50 }
}
```

响应结构：

```json
{
  "messages": [],
  "nextCursor": null,
  "hasMore": false,
  "total": 238
}
```

- `limit` 默认 50，必须为 1–150 的整数；字符串、浮点数、`null`、越界值均返回 HTTP 400。
- 不提供 `cursor`，或传 `null` / 空字符串时，从当前最近 `limit` 条开始；通常前端应从 `state.messagePage.nextCursor` 继续。
- 有游标时，仅返回 `(createdAt, _id)` 严格小于游标边界的最近 `limit` 条，批内依旧升序排列。ID 使用 ASCII 字符顺序比较，不用语言环境排序。
- 客户端保留已加载范围最早一页的继续游标，轮询时不能用新的最近窗口游标覆盖它。失败重试保持原游标；成功才前移。历史回复不能作为刚收到的回复再次提示。
- 游标边界保存完整排序键，不要求边界记录仍然存在。翻页间新增记录不会把已存在旧记录的序号挤走；软删除记录不再返回，同毫秒记录以 ID 分开。`createdAt` 和 `_id` 为不可编辑的排序键，人工修订只更新 `updatedAt`。

## 游标与权限边界

游标是版本化的规范 Base64URL 载荷和 HMAC-SHA256 签名，包含家庭 ID、边界时间和边界消息 ID。客户端应将它视为不透明字符串，不能构造或解析后修改。类型、长度、编码、结构、版本、时间/ID、家庭和签名都严格验证；损坏、篡改或跨家庭使用返回 HTTP 400，可提示刷新列表重试。失效会话或禁用账号仍优先返回 HTTP 401。

首次需要签发继续游标时，服务端通过现有存储 CAS 在家庭文档上懒初始化随机 `historyCursorSecret`。并发实例共用胜出的持久密钥；重启不换密钥。公开 `room` 仍只有 `{id, name}`，不得展开原始家庭文档或将密钥写入日志。没有继续页时不需要初始化密钥。

分页是当前数据上的 keyset 遍历，并非数据库时间点快照。新消息由最近窗口轮询补入；已删除消息不会保留在历史页中。`total` 是每次请求当前未删总量，可随新增/删除改变。当前家庭最多 300 条消息，已有存储读取上界覆盖该容量；此改动未提高消息/文件配额，也未改动 3D 分段下载或权限逻辑。

## 本轮验证

`test/message-history.test.js` 使用隔离临时目录和真实本地 HTTP 请求验证：旧协议、全部历史覆盖、同时间戳排序、边界删除、翻页中新增/删除/编辑、严格参数/签名验证、跨家庭隔离、历史媒体刷新/空间状态、退出/过期/禁用账号，以及多实例并发密钥初始化与重启续页。

媒体过期用测试时钟跨过真实缓存阈值验证；没有等待或声称完成真实设备弱网/浏览器点击验收。测试不连接云、不读取私人凭据、不新建云家庭。
