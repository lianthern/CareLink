## TRTC 启用条件仍未满足

本次只读目标为整合 worktree 当前私有部署配置文件，输出字段存在性而不输出值。`AI_REALTIME_PROVIDER`、`AI_REALTIME_TRTC_APP_ID`、`AI_REALTIME_TRTC_SDK_SECRET`、`AI_REALTIME_TRTC_SECRET_ID`、`AI_REALTIME_TRTC_SECRET_KEY`、`AI_REALTIME_LLM_JSON`、`AI_REALTIME_TTS_JSON` 七项均缺失；房间权限确认、清理控制和独立清理开关均未就绪。预检按设计非零退出，详见 JSON。没有执行 `--probe-llm`、Start、购买、开通、扩权或创建 Timer。

复现与影响：对同一私有配置执行 `node scripts/check-trtc-readiness.mjs --config <私有配置路径>` 即可看到上述缺项；`server/ai-realtime-trtc.js:17` 起默认关闭，`server/public/ai-realtime.js` 禁用开始且不请求麦克风。故**当前不能验收“真人与 AI 实时语音已可使用”**，普通文字/照片聊天不受此开关影响。

后续获准开通时，按 [TRTC 准备](TRTC-READINESS.md) 和 [开通方案](TRTC-SETUP-PLAN.md) 集中完成：

1. 确认实际账户权益、费用及控制 API 权限，填写独立服务端凭据并验证房间权限确实生效；本次离线报告不能替代账户查询。
2. 选择 TRTC 直连 hy3 的凭据授权范围或受限桥接。普通 CloudBase SDK 聊天不等于外部流式接入；桥接目前是设计，未实现。
3. 以真实链路验证模型 SSE、请求头、音色、机器人音频和插话打断。本次重新读取官方资料：TRTC 要求完整 `APIUrl` 等 LLM 配置；CloudBase 的 hy3 流式示例携带 `Accept: text/event-stream`。仅有 JSON 字段无法证明双方实际兼容。[TRTC 开始接口](https://cloud.tencent.com/document/product/647/108514)、[LLM 配置](https://cloud.tencent.com/document/product/647/115413)、[CloudBase cURL](https://docs.cloudbase.net/ai/model/curl-access)。
4. 在明确授权后部署私有独立清理并实测无网页访问时过期/崩溃任务的 Stop、失败重试与告警。`server/ai-realtime-cleanup.js:10` 默认不工作；存在入口不是已运行 Timer，前端10分钟也不是供应商硬费用上限。
5. 完成静音/挂断、关闭重开重试同一 Stop、断网/切后台、会话撤销和真人麦克风/扬声器验收，再开放入口。

## 优先完善与现场操作清单

以下为未取得的验收证据或后续改善，未发现需要本分支额外修复的发布阻塞。

1. **先做真实 Link 2 → Windows → 指定平板闭环。** 启动前只读核对既有绑定，保留用户选定的目标，不为验收重新签发覆盖；相框显示一张照片且前台空闲。现场驻足后只在目标相框收到邀请；拒绝不调用 AI，确认只提问一次且不自动开麦/朗读。拔线、断网、恢复、关闭程序后不补发历史队列。超过7天或退出配对后要重新配对/绑定，旧令牌不续期。
2. **真人与实体平板验收。** 家人从“＋”寄照片和自己录的原声；相框点“听原声”，再点“说一说”录音、试听、发送；家人收到绑定原照片的回复。再手动朗读/语音输入，检查音量、授权拒绝和切后台停止。Chrome 合成录音不替代这一项。
