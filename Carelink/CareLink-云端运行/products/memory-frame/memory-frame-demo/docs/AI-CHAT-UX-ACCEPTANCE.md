# AI 聊天入口与实时语音界面验收

日期：2026-09-23。实施分支 `codex/ai-chat-ux`，基线 `d5f9d28`。仅修改 `server/public/`、相关前端测试和本文档；等待总控审查集成，未部署。原公网 0.4.4 不包含本次界面。

## 用户可见变化

- 首页家庭名称下方仍为“和 AI 聊天 / 实时语音”；家人端底部“首页 / 中央加号 / 我的”顺序不变，相框端共用聊天入口。
- 文字切换到实时语音后，点击“返回文字聊天（内容已保留）”、关闭语音窗口或按 Esc，均回到原文字窗口，保留最近六轮、未发送文字、已选照片和已有原声。切换会停止录音/朗读、取消未完成回答及行动确认卡；原声不会自动发送。关闭文字窗口、离开页面或退出身份仍清除这份临时聊天，不写入持久存储。
- 家庭照片选择默认折叠；从具体记忆进入时展开。无照片时不显示读取照片的勾选项。长照片标题可换行，窗口滚动时保留标题与关闭按钮。
- 打开文字聊天聚焦输入框；Enter 保持换行，Ctrl/⌘ + Enter 发送，中文输入法组合期间不触发快捷发送。完成回复恢复输入焦点；关闭回到发起入口。保留原生模态对话框键盘行为，背景页面不可交互。
- 聊天功能检查失败可以原地重试并保留草稿；检查期间可以打字，发送/录音暂不可用。取消或切换后可重新检查，不停留在无出口的加载状态。
- 未开通、未知服务、浏览器不支持和检查失败均禁止开始实时语音；普通界面不展示供应商配置字段。可用性检查只表示可以尝试连接，连接成功前不显示已连接。
- 麦克风拒绝、未找到设备、被其他应用占用分别说明恢复办法。挂断立即释放本机音轨，在停止响应返回前显示“正在挂断”并禁用再次开始；远端结束未确认时明确显示不确定状态。
- 三个变化的 CSS/JS 静态地址更新为 `0.4.5-ux1`，避免部署时混用十分钟缓存内的旧窗口代码；这不是运行服务版本号。

## 复验方式

从 `memory-frame-demo` 运行，PowerShell 示例：

```powershell
$env:AI_UX_PLAYWRIGHT='C:/Users/15pro/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright'
$env:AI_UX_CHROME='C:/Program Files/Google/Chrome/Application/chrome.exe'
$env:AI_UX_SCREENSHOTS=(Join-Path (Get-Location) '.tools/ai-ux-screenshots')
node --test test/ai-chat-browser.test.js test/ai-conversation-ui.test.js test/ai-realtime-ui.test.js test/ai-voice.test.js test/family-contact-ui.test.js test/family-ui-lifecycle.test.js test/account-ui.test.js
```

换电脑时将前两项改为已有 Playwright 模块目录和 Chrome 可执行文件。浏览器测试不增加应用依赖、不安装浏览器；未显式提供这两项时会跳过，不能把跳过写成通过。截图为 `.tools/ai-ux-screenshots/{home,text,realtime}-{320,390,1280}.png`，不进 Git；设置第三项即可重建。测试结束会关闭自身上下文、浏览器和回环服务。
