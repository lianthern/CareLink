# 家庭首页活动状态与统计

2026-09-23。本轮只补后台协议，不改云部署配置、前端、原照片/原声或空间导入通道。

## 相框明确上报活动

`POST /api`，使用相框会话的 Bearer token：

```json
{
  "action": "framePresence",
  "data": {
    "messageId": "m_<room>_<message>",
    "activity": "viewing"
  }
}
```

`activity` 只允许以下值：

| 值 | 上报条件 |
| --- | --- |
| `viewing` | 当前显示同家庭、未移除的顶层记忆卡 |
| `listening` | 当前记忆卡有原声，播放器已实际开始播放 |
| `recording` | 当前记忆卡正在录制回信，麦克风已实际启动 |
| `spatial` | 当前记忆卡的空间为 `ready`，自有查看器已实际显示 |
| `idle` | 页面隐藏、夜间时钟、没有当前记忆或已停止活动；`messageId` 必须为空或省略 |

后端验证会话角色、所属家庭、消息未删除、顶层类型，以及 `listening` 的原声 / `spatial` 的 ready 条件。`photo` 是已有存储模型对顶层记忆卡的类型名称，也包含纯文字、原声或空间链接卡，并不等于一定有图片。回信 `reply` 不能作为当前记忆目标。

家人会话调用返回 403；跨家庭、已移除、回信或不存在的目标返回 404；未知状态、错误空闲参数、缺少原声返回 400；空间未准备好返回 409。相框会话过期或撤销返回 401；写入的 CAS 回调再次检查权限，阻止验证期间刚被移除的会话继续更新。

时间全部由服务端生成；请求中的 `updatedAt`、`expiresAt` 等额外字段不能伪造新鲜程度。返回：

```json
{
  "ok": true,
  "accepted": true,
  "updatedAt": 1790136000000,
  "expiresAt": 1790136045000,
  "retryAfterMs": 10000
}
```

- 活动或记忆切换立即上报；相同活动建议每 15 秒心跳一次。相同 `messageId + activity` 在 10 秒内只读去重，`accepted:false`，不反复写存储。
- `retryAfterMs` 表示同内容心跳距离下一次可持久化的时间，不禁止立即报告活动变化。现有 HTTP 每 IP 600 次/分钟上限继续生效。
- 前端应串行发送活动请求，并合并等待中的最新活动，避免旧网络请求在停止录音或切图后才抵达。后台记录服务端接收时间，已持久化的较新事件不会被较早进入内容验证的请求覆盖。只读去重的心跳不更新顺序标记。
- 页面轮询 `state` 只代表设备在连接；不会新增、续期或推断观看/聆听/录音状态。也不从音频收据、配对时间、AI 结果或时钟推断家人的健康、情绪或实际注意力。
- 这是相框软件明确上报的活动，不是对人在看屏幕、听声音或说话的生物识别证明。浏览器权限失败、播放失败或查看器尚未加载时，前端不能提前上报相应活动。

## `state.framePresence`

```json
{
  "online": true,
  "activity": "viewing",
  "messageId": "m_<room>_<message>",
  "frameId": "s_<session hash>",
  "frameName": "客厅相框",
  "updatedAt": 1790136000000,
  "expiresAt": 1790136045000,
  "message": {
    "id": "m_<room>_<message>",
    "title": "老家的晚饭",
    "imageURL": "/media/<temporary access>",
    "hasAudio": true
  }
}
```

活动上报 45 秒后过期，且不会超过该会话本身有效期。没有上报、过期或无有效相框时，`online:false`、`activity:null`、`messageId:null`、`message:null`。仍有效但陈旧的会话可以保留设备名称及最后上报时间；从未上报时 `updatedAt/expiresAt` 为 `null`，没有有效相框时 `frameId:null`、`frameName:''`。UI 可结合 `serverTime` 和 `expiresAt` 在轮询中断时及时停止显示“正在”。

刚上报的记忆随后被移除，或其原声/空间变得不可用，返回 `online:true, activity:'idle'`，清空当前记忆预览，不继续宣称正在看已移除的照片。过期/撤销会话完全排除。多个相框存在时，优先选择近期明确活动的相框，再选择近期空闲相框；同层选择最新上报，最后才是陈旧或从未上报的设备。

`message` 是经过家庭检查的当前预览，即使该记忆位于现有 `state.messages` 最近 150 条之外也可显示标题与照片。它不包含原声 URL、模型内容、空间签名地址或完整编辑数据；未实现历史分页前，窗口外的详情仍需明确告知无法在当前列表打开。

## `state.stats`

服务端在截取 150 条列表窗口之前计算本家庭全部未删除消息，范围受已有每家庭最多 300 条消息限制；不会根据上传文件表、缓存、最近窗口或保留的私有模型数量猜测统计。

| 字段 | 精确定义 |
| --- | --- |
| `photos` | 有 `image` 的顶层 `photo` 消息数；回信继承的父照片不重复计数 |
| `voices` | 有 `audio` 的全部可见消息数，包括家人寄来的原声和相框回信 |
| `spatial` | 空间状态为 `ready` 的可见顶层消息数 |
| `replies` | 未移除的 `reply` 消息数 |
| `memories` | 全部未移除消息数，包含顶层卡和回信 |

这些都是**记忆消息条数**，不是去重后的文件数或模型数。重复引用同一个已完成空间的两条记忆计为两条空间记忆；一条带照片和原声的记忆同时计入照片与原声，分类不能相加当总数。未发送的上传、导入中/失败空间、已移除记忆及没有可见消息引用的私有模型不计入。父记忆移除但回信仍保留时，回信及其原声仍计数。

## 人物与时间轴字段审查

本轮无需新增人物模型：已有 `person {name, relation}` 接口仅家人可编辑，姓名在同家庭内作为去重标识；`state.people` 返回称呼和家庭补充的关系说明。它不是人脸识别结果，也不是具有出生年月或结构化亲属边的家谱。相同称呼会更新同一记录，不能表达两位同名人物的身份区分。

记忆已有 `card.people`（称呼数组）、`card.year`（自由文本）、`card.place`、`card.summary`、`card.confirmed`、`card.source`，可用于人物筛选、年代分组和家人确认标识。`card.year` 可以是“20世纪80年代”或“不详”，不能强行变成精确日期；缺少回忆年份时可使用 `createdAt`，但必须标为“收录时间”，不能冒称事情发生时间。AI 未确认字段应保留其草稿属性。

现有 `state.messages` 仍是最近 150 条；全量统计不代表人物页和时间轴已具备无限历史查询。完整遍历超过窗口的历史需要后续专门的分页接口，本轮未扩大该范围。
