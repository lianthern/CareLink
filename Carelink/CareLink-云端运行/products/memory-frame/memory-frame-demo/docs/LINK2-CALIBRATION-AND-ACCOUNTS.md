# Link 2 现场接线、Calibration 与账号怎么用

核对日期：2026-09-24。线上相框版本为 **0.4.9**，设备运行包仍叫 `Kevin-Link2-0.4.8-PRIVATE`；两者版本号不同不影响现有事件协议。

**调摄像头参数在 Windows 程序里操作；管理它发给哪台相框，才登录家人端。** 现有源码和交付 EXE 中没有名叫“Calibration”的入口或独立账户。下面按现场所说的“Calibration＝检测区域/驻足阈值调节”说明；如果现场指的是影石软件中的另一项校准，需要对照那个窗口名称，不能用本说明替代厂商功能。

## 现有 Kevin 先这样打开

1. Windows 只接一台 Link 2，使用 USB 数据线。关闭占用摄像头的相机、会议、OBS、Link Controller。
2. 在原 Kevin 平板/设备的原浏览器打开相框端。保持页面前台、有照片、空闲；无需登录成家庭管理员。0.4.9 的“退出展示”只退出大图展示；“设置 → 退出配对”才会失去原配对，现场检查不要点后者。
3. 完整解压 `Kevin-Link2-0.4.8-PRIVATE.zip`，双击根目录 `START-KEVIN.cmd`，保留控制台和检测窗口。不要只复制 EXE，也不要再启动第二份检测程序。
4. 现有配置是 `living-room-link2 → Kevin`，不要为了调参数重新签发或轮换令牌。Windows 和相框分别能访问互联网即可，不要求同一局域网。

摄像头通过 USB 接到 Windows；Windows 检测器把驻足事件经云端定向送到 Kevin。摄像头画面、头部框只在本机调试显示，不上传视频，也没有人脸身份识别或视线校准。

## 在 Windows 调 Calibration

运行后找标题为 **`Insta360 Link 2 - Dwell Detector Debug UI`** 的窗口，右侧标题为 **`Link 2 detector parameters (live)`**。源码窗口初始大小为 1500×930；右侧看不全时先放大窗口。

先固定摄像头朝向，让一个人站在实际观看相框的位置。调试画面左侧：黄色虚线框是 ROI；绿色头框表示通过大小/边缘/ROI 基本过滤，红框表示未通过。成功观察应有 `SDK: OK`、`Stream: OPEN`、`Heads: … / usable 1`。**两个或更多有效人头会使本次样本无效**；绿色框也不等于整段驻足已完成。

| 英文参数 | 默认值 | 含义和现场操作 |
| --- | --- | --- |
| `ROI left / right / top / bottom` | `0 / 1 / 0 / 1` | 检测区域四条边，按画面宽高的 0–1 比例。左上角是 0,0；缩小到实际看相框的人头所在区域，可排除旁边路人。判断的是**头框中心**是否在 ROI 内，不是整个人体轮廓。 |
| `Minimum head width / height` | `0.04 / 0.08` | 头框最小宽/高，占画面比例。正常距离的人总是红框时，先检查 ROI 和完整入镜，再小步减小；远处路人容易算入时，可适当增大。 |
| `Complete-head margin` | `0.00` | 画面边缘留白；要求头框完整处于此边界内。通常先保持 0。 |
| `Polling frequency` | `5 Hz` | 每秒检测次数，先保持默认。 |
| `Rolling window` | `4 s` | 统计有效样本的时间窗，默认 20 个样本。 |
| `Required valid ratio` | `80%` | 默认至少 16/20 个样本有效。先保持默认；避免只靠降低比例掩盖画面问题。 |
| `Minimum dwell` | `4.0 s` | 持续驻足门槛。要减少路过误触可增大；只减小此项、仍保留 4 秒窗口，不会变成瞬间触发。 |
| `Missing tolerance` | `0.8 s` | 短暂丢失目标的容忍时间，先保持默认。 |
| `Cooldown` | `30 s` | 触发后冷却时间。 |
| `Require confirmed leave before rearm` | 勾选 | 需要先确认人离开再重新布防；仅原地等满冷却时间，不一定重新触发。建议保留。 |
| `Maximum center jump` | `0.25` | 相邻目标中心变化阈值，先保持默认。 |
| `Minimum / Maximum area ratio` | `0.25x / 4.00x` | 相邻头框面积变化范围，用于判断是否换了目标，先保持默认。 |

推荐调节顺序：**摆好相机 → 保证一个有效头框 → 调 ROI → 必要时调头框大小 → 最后调驻足时间**。每次只改一组，离开画面后再进入验证。不要用 ROI 把“有人停留”解释成“眼睛正在看相框”。

**当前没有保存参数功能。** 滑块实时修改本进程的内存配置；源码没有参数文件加载/保存，私有 `presence.private.json` 只管连接，不保存这些阈值。关闭或重启检测程序后恢复默认。现场调好后把参数抄到下表或截下右侧参数区，下次启动按记录恢复；不要把 `presence.private.json` 的令牌一起截图。

| 项目 | 现场记录 |
| --- | --- |
| 相机位置/朝向、观看位置 | |
| ROI left / right / top / bottom | |
| Minimum head width / height | |

| 其他修改项 | |

## 看云端是不是绑对相框

用**家庭管理员**登录家人端 → 页头“设置”（或“我的 → 设置”）→ **“管理相框驻足邀请”**。普通家人账号和相框页面不会显示这个管理入口。核对 `living-room-link2` 的目标确实是 Kevin，且“已启用”；同名设备还要核对 ID 尾码，不能只凭名字。

本次 2026-09-24 09:05（北京时间）实际读回：Kevin 配对有效、绑定启用，**页面离线**；“有效”与“正在打开页面”是两件事。现有绑定最晚到 **2026-09-30 18:40:03（北京时间）**，退出配对、移除或停用会提前失效。具体尾码在私有说明中。

如果 Kevin 打开后看到“待配对相框”，说明该浏览器没有可用原配对。先确认是不是换了浏览器/使用无痕窗口/清了网站数据；还在原浏览器时不要另建家庭。确实需要重配时：

1. 家人管理员进入“我的 → 邀请家人 / 配对 → 配对相框”。
2. 在目标相框浏览器打开生成的链接；填写“相框称呼”，点“完成配对”。配对链接有效 24 小时。
3. 管理员重新核对目标设备；旧目标失效时停用旧绑定，给对应的新设备签发独立传感器令牌，再更新那台 Windows 的私有连接配置。

即使新设备仍叫 Kevin，它的配对身份也和原来不同。第二台相框需自己的设备标识与令牌，不能复制 Kevin 的私有包直接当成第二套绑定。

## 现场验收与故障定位

让一个人在有效区域保持约 4–6 秒，观察三个不同结果：

1. 本机状态从 `SEARCHING` → `OBSERVING` → `COOLDOWN`，控制台有 `captured presence.dwell`：检测完成。
2. 控制台有 `uploaded … status=200`：云端接受事件。
3. Kevin 上出现邀请，约 15 秒内点确认后出现照片文字问题：相框交互完成。

只有前两项，不能当作平板显示成功。已上传却没邀请时，检查 Kevin 是否原配对、前台、有照片、非夜间时钟且空闲；关闭设置/更多菜单、AI、录音、原声播放与 3D 窗口后重试。旧邀请不会排队等忙完再弹。重新测试先离开检测区，等待冷却，再回来。现场完成后用 Ctrl+C 或关闭检测窗口结束。

401/403 表示上报鉴权失败，上传器会停止检测进程。先由管理员检查绑定和到期时间；不要把家人密码、旧 MVP 共享 token 或相框登录会话填进传感器配置。

### 本机关机后怎么继续运行

已部署的云网页、家庭内容和后端不依赖这台开发电脑保持开机，仍受云端服务状态与有效配置影响。**USB 接在本机的 Link 2 采集程序会随本机关机停止**，因此新的驻足邀请不会继续产生；相框也必须自己保持开机、联网并打开原配对页面。把代码放到云函数不能让云端直接读取家里 USB 摄像头。

需要开发电脑关机后仍有驻足邀请时，把设备采集迁到一台保持开机的 Windows 电脑：

1. 在现有检测窗口记录 ROI 和修改后的阈值；它们不会写入私有连接文件。
2. 停止旧 Windows 的 `START-KEVIN`/检测器，再拔下 Link 2。
3. 将**完整** `Kevin-Link2-0.4.8-PRIVATE.zip` 通过私密渠道复制到常开 Windows 并解压，保留 `camera`、`device`、`runtime`、`private-access` 目录结构；不能只复制 EXE。
4. 只连接一台 Link 2，确认那台电脑能访问现有 HTTPS 服务，再双击 `START-KEVIN.cmd`，按记录恢复阈值。首次迁移仍需在现场处理系统依赖/摄像头权限并验收。
5. 原 Kevin 相框、家庭、传感器设备标识都保持不变时，迁移采集电脑**不需要新建家庭、重新配对或轮换 token**。不要让两台采集器同时使用同一个绑定运行；如果改成另一台相框，才按前述流程建立对应绑定。
6. 重新观察 `captured`、`uploaded status=200` 和 Kevin 屏幕邀请。当前启动器是交互式窗口程序，没有已配置的 Windows 服务/开机自启；机器重启后仍需启动，调参仍需按记录恢复。不要把“迁移文件成功”当作无人值守已经完成。

当前 Kevin 配对最长到 2026-09-30；常开机器也不能延长它。长期无人值守还需要处理配对/传感器到期和采集器自启动、参数持久化，这几项本轮没有改动。
