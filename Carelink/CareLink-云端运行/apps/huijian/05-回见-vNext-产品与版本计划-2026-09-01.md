# 回见 vNext：产品与版本计划

日期：2026-09-01

状态：已拍板，M0 + M1 代码验收通过；待 Android / iPhone 真机 canary 与发布决策
基线：当前公网已经是“选一张照片 → 阿见先说看见了什么 → 问一个问题 → 用户用文字回答”的单图体验。

## 一句话决策

下一版不要同时做“语音、模板商城、3D、粒子、长期记忆”五个新产品，而要把它们收进同一条手机端旅程：

> **先给一张照片，阿见用文字或语音陪你把它说出来；说完以后，再把这段记忆做成一页、一本或一个可进入的画面。**

优先级是：**语音降低表达成本 > 单图主链跑顺 > 单图/多图结果分流 > 可见的持续记忆 > 3D 与粒子增强沉浸。**

## 我建议直接拍的六个板

### 1. 黑色方向成立，但不是“所有页面都黑”

- 采集、看图、对话阶段用黑色/深夜蓝，像一个安静的暗房，照片是唯一高亮主体。
- 导出的一页、相册和打印结果保留相纸浅色；否则黑底会降低阅读、打印和分享适配。
- 产品形成明确的双世界：**黑色记忆工作台 → 浅色可保存成品**。

### 2. 首次体验不要在上传前拦登录

首屏写“选一张照片”，不写“先登录后上传”。用户先在访客态体验一次完整价值：选图、阿见看图、回答、看到结果。

登录只在以下时刻出现：

- 保存到“我的回见”，需要跨设备继续；
- 建立多图相册或长期合集；
- 之后再次打开并延续同一段记忆。

本地导出一张图片/PDF 不应强制登录。隐私说明与 AI 看图同意仍在选图前明确出现，它与账号登录是两件事。

### 3. 先对话，再选成品；不要先让用户逛模板

模板选择放在第一次回答之后。用户还没感受到“阿见真的看见了”，就让他选择十种风格，会把产品变成普通图片编辑器。

第一轮对话结束后只出现两个结果动作：

- **留下这一页**：当前照片直接生成单图记忆页；
- **再加几张，做成一本**：进入多图选择与编排。

### 4. 语音先做“输入方式”，不要一开始做全语音伙伴

P0 是回答框里的“按住说话 / 点按录音”：

- 语音转文字后先给用户看，可修改，再确认；
- 原音频是否保存由用户明确选择，默认只保留确认后的文字；
- 麦克风拒绝、识别失败、无声超时都能立刻回到文字输入；
- 阿见的问题先继续用文字，TTS 朗读放到后续实验。

这样语音真正解决的是“说比打字容易”，不会立刻引入打断、回声、播报速度、公共场所尴尬等整套语音代理问题。

### 5. 模板要分“结果形态”和“视觉风格”

不要把所有选择都叫模板。

结果形态只保留三种：

1. **一页回忆**：一张照片 + 用户原话，默认主结果；
2. **一本相册**：多张照片 + 封面 + 翻页，默认多图结果；
3. **立体记忆**：单图 2.5D/粒子化的沉浸查看，先标实验。

视觉风格第一批只做三套，且三种结果尽量共用：

- 傍晚相纸：现有阿见语言的默认版；
- 黑色碎片：来自参考视频的黑底粒子方向；
- 极简留白：适合海报、打印和长辈。

先证明三种结果有人完成、保存和分享，再扩风格数量。

### 6. “持续记忆”先做用户看得见的合集，不先做神秘人格记忆

第一版持续记忆的单位不是“AI 永远记得你”，而是用户能看见、能编辑、能删除的**记忆合集**：生日、旅行、毕业、这一年、某个人。

每条确认后的记忆至少绑定：

- 原照片或照片引用；
- 阿见看到的客观事实；
- 问题与用户确认后的原话/语音转写；
- 拍摄时间、创建时间、合集；
- 结果形态、风格 ID 与版本；
- 是否保存原音频、是否允许公开/分享。

“今年的多张照片保持同一种风格”通过合集的 style profile 实现，不需要模型先建立一套不可见的人格画像。

## 手机端主流程

```text
打开回见
  ↓
黑色首屏：只做一件事——选照片
  ↓
单张 / 多张都可选，但先聚焦当前一张
  ↓
照片进入暗房：轻微透视，粒子从散到聚，只发生一次
  ↓
阿见先说“我看到了” → 只问一个问题
  ↓
用户文字回答 / 按住说话 → 可编辑转写 → 确认
  ↓
留下这一页 ─────────────→ 单图记忆页 / 海报
  └─ 再加几张，做成一本 → 多图选择 → 相册模板 → 翻页成品
  ↓
本地导出不登录；保存合集/跨设备继续时登录
```

不要在首屏显示“单图、相册、海报、3D、风格、空间”六个入口。入口只有照片，分叉在用户已经说出一点内容之后发生。

## 参考视频该学什么

目标视频把黑色全屏、照片粒子/网格化、深度变化、圆形麦克风和记忆画面切换做成了一个统一体验。2026-09-01 页面约显示 8.8 万点赞、5.6 万收藏和 2133 条评论；一条独立公开讨论也有人明确认为“网格/纺织化照片 + 周围粒子”符合“记忆碎片”的感觉，并把照片称为记录的锚点。[目标视频](https://www.xiaohongshu.com/explore/69231768000000001e00923c) · [公开讨论](https://linux.do/t/topic/2125064)

回见应借鉴：

- 照片不是卡片列表，而是屏幕中央唯一的“记忆物体”；
- 语音按钮与照片处于同一空间，表达像对着照片说；
- 粒子承担“看见、聚拢、切换、收束”的状态含义；
- 黑色给照片和粒子留出亮度层级。

回见不应照搬：

- 粒子持续满屏运动；
- 大量导航、参数调节器和视觉控制暴露给普通用户；
- 粒子遮挡正文、按钮和照片人物；
- 因为一条爆款就断言所有用户都喜欢粒子。

## 3D/透视怎么做

先做 2.5D，不先承诺真正的 3D 照片：

- 第一层：整张照片随手机陀螺仪或手指产生很轻的卡片透视；
- 第二层：对可用照片生成前景/中景/背景深度层，做小幅视差；
- 第三层：只有在“阿见看图”和“进入成品”时，用粒子从轮廓散开/聚拢；
- 人脸、文字和主体边缘出现拉裂时自动回退为普通照片；
- 低性能设备与 `prefers-reduced-motion` 只显示静态图。

2.5D 是结果层的增强，不参与记忆内容本身。没有它，用户仍然能完成整条旅程。

## 电脑端先怎么处理

现在不单独发明第二套电脑产品。先做响应式伴生版：

- 单图时左侧固定照片/立体预览，右侧是阿见与输入；
- 多图时左侧变照片胶片带，中央预览相册，右侧改风格与导出；
- 手机端负责随手说，电脑端更适合整理、排序和导出。

只有活动主办方/摄影师的真实使用证明需要批量管理时，再把桌面端升级为独立工作台。

## 版本顺序

### M0：效果验证，不动主链

做一个独立交互样片，同一张照片可切换：

- 当前平面版本；
- 轻透视 + 一次粒子聚拢版本。

冻结同一段文案和同一张图，只观察用户是否更愿意停留/开口、是否更容易理解“记忆正在形成”，以及普通手机是否顺滑、人物是否变形。没有隔离比较前，不把粒子写成产品卖点。

### M1：语音版单图主链

交付后用户能在访客态完成：选一张照片 → 阿见先看见 → 文字或语音回答 → 修改转写 → 留下一页 → 本地导出。

这一阶段包含黑色工作台与轻透视；完整粒子系统、登录、长期记忆、多图模板不阻塞上线。

### M2：单图/多图结果系统

把“结果形态”和“视觉风格”做成稳定数据模型；上线一页回忆、一本相册、实验性立体记忆三种结果，三套共用风格。多图必须真的有封面、多页、翻页和导出，不能退化成长海报。

### M3：账号与持续记忆

在用户第一次看见成品后增加“保存到我的回见”。上线合集、继续添加、统一风格、跨设备打开、导出和删除；登录失败不影响本次本地结果。

### M4：UNSEEN 空间桥接

只有当同一活动/同一批照片有真实多人数据时，再增加“放回现场/进入空间”。不要把普通单人相册强行包装成空间产品。

## P0 / P1 / 实验线

| 级别 | 做什么 | 暂时不做什么 |
|---|---|---|
| P0 | 访客单图、语音转文字可编辑、黑色工作台、单图结果页、文本兜底 | TTS 对话、强制登录、完整粒子引擎 |
| P1 | 多图相册、三种结果形态、三套共用风格、合集保存 | 模板商城、自动长期人格 |
| 实验 | 深度图 2.5D、粒子聚拢/切换、声音驱动微动 | 满屏常驻粒子、重 3D 编辑器 |
| 后置 | 跨年持续记忆、多人空间、桌面批量工作台 | 未验证前的大规模重构 |

## 需要观察的事件

不先编业务阈值，先在现有种子用户冲刺里补这些诊断事件：

- `voice_started / voice_transcribed / voice_edited / voice_confirmed`
- `result_path_selected`：一页 / 一本 / 立体记忆
- `style_selected`
- `local_exported`
- `save_prompt_shown / login_started / memory_saved`
- `collection_reopened / collection_appended`
- `depth_enabled / depth_fallback / reduced_motion_used`

继续沿用现有七天冲刺的外层证据：真实上传、回答、成书/结果完成、分享、再次打开和按场付费。功能使用量只能解释漏斗，不能替代用户价值。

## 下一轮实现合同（普通任务，不用 `/goal`）

```text
在不退化当前“单张照片 → 阿见先说可见事实 → 只问一个问题 → 用户原话成页”体验的前提下，完成回见 vNext 的第一个可测试切片：访客可以用文字或按住说话回答，看到可编辑的语音转写，再生成并本地导出一页回忆；同时提供一个独立、可关闭的轻透视 + 单次粒子聚拢效果样片，与当前平面版本并排比较。

活动真相：以当前公网 https://huijian.maxxam.xyz/ 的可见流程、docs/agent-experience.md 和本文为意图入口；开工先核对本地 main、origin/main 与生产版本，保留 README 现有用户改动，不把未提交战略材料混进功能实现。

范围：手机端单图主链、语音转文字、可编辑确认、文字兜底、本地导出、轻量 2.5D/粒子实验；不包含登录、服务端长期存储、多图相册、TTS、完整 WebGL 粒子系统、桌面批量工作台或部署。

保持：阿见先证明看见再提问；不猜身份/关系/情绪；用户原话不润色；看图或语音失败不锁死；减少动态模式可完成同样流程；没有效果增强也能完整使用。

仅在以下全部成立时完成：
1. 手机真实渲染中，访客能分别走通文字和语音两条回答路径；语音转写在确认前可编辑，拒绝麦克风和识别失败能回到文字输入。
2. 结果页保留原照片与用户确认后的原话，可在不登录的情况下本地导出；刷新/不保存的边界与实际行为一致。
3. 效果样片能在同一张图、同一文案下切换平面/轻透视粒子版；人物边缘异常、低性能或减少动态时自动回退静态图。
4. 当前单图文本流程、AI 弃权边界和基本可访问性不退化，并保存手机首屏、看图、语音转写、结果页和降级态的真实截图/录屏证据。
```

## 本轮未替 Max 拍死的事项

- 登录供应方与数据存储位置；
- 原始语音是否提供可选长期保存；
- 第一批三套视觉风格的最终命名；
- 立体记忆是否以后成为付费能力；
- 回见品牌是否最终继续作为 UNSEEN 2.0 的结果层，还是在真实行为分叉后独立。

这些选择不阻塞 M0/M1；先拿到实际使用，再决定成本更高、不可逆的部分。

## 2026-09-01 并行执行与验收安排

本轮用三个独立 WorkTree 并行，最终只合入 `codex/vnext-integration`：

| 分支 | 职责 | 合入前必须给出的证据 |
|---|---|---|
| `codex/vnext-voice` | 浏览器语音输入、可编辑转写、错误降级、纯模拟自动化测试 | commit、测试日志、仍需真机确认项 |
| `codex/vnext-spatial-export` | 原样/轻立体切换、单次轮廓粒子、reduced-motion、PNG 与打印导出 | commit、测试日志、移动端/导出人工确认项 |
| `codex/vnext-qa` | 独立检查主链、响应式、服务健康和错误态 | P0/P1/P2 清单、复现步骤、截图或日志 |
| `codex/vnext-integration` | 只负责整合、冲突处理、回归验收与范围守门 | 合并后统一测试、真实浏览器截图、最终未完成项 |

合入门槛按顺序执行：

1. **结构门槛**：Node 语法检查、自动化测试、服务健康探针全部通过；任一失败不进入视觉验收。
2. **主链门槛**：演示照片能完成“阿见观察 → 一个问题 → 文字回答 → 原话成页 → PNG/PDF”；AI 失败时明确“不猜”且仍能完成。
3. **语音门槛**：成功、停止、无声、拒绝权限、网络错误五条状态有确定 UI；任何错误都不清空已有文字，也不锁住回答框。
4. **效果门槛**：同一照片可即时比较原样/轻立体；粒子只在开启或换图时短暂出现，不常驻、不盖按钮；减少动态时只能走静态版。
5. **导出门槛**：PNG 保留原图、日期、问题和用户确认后的原话，长中文不截断；不登录可下载；打印样式不包含操作按钮。
6. **手机门槛**：至少在 360、390、430 CSS px 检查首屏、对话、输入、结果四态，无横向滚动、按钮可点、键盘出现后仍能提交。
7. **范围门槛**：本轮不带入登录、多图、长期记忆、TTS、真实深度分层、部署；这些只留在 M2–M4。

最终判断只有三种：

- **通过**：所有 P0 门槛成立，可交给真实手机试用；
- **有条件通过**：文字主链完整，语音或效果仅有明确的设备兼容限制，且自动降级成立；
- **退回**：会丢原话、错误后无法继续、导出不可用、效果遮挡内容，或旧单图流程退化。
