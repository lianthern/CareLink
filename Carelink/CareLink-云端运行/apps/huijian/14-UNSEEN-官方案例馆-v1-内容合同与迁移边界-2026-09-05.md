# UNSEEN 官方案例馆 v1：内容合同与迁移边界

日期：2026-09-05
内容版本：`official-gallery/v1`
当前状态：版本控制中的官方只读内容源；没有账号、发布后台或 UGC

## 1. 这版是什么

第一版案例馆是 UNSEEN 自己维护的策展式能力说明，不是开放社区。

- 「看看」只展示由 `UNSEEN 官方` 发布的案例；
- 中央「＋」只接用户自己拍摄或选择的照片；
- 「我的」只展示当前设备上的个人内容；
- 案例可以被打开和阅读，但不能被一键复制成用户照片、回忆或 World Labs 任务；
- 当前不提供普通用户注册、发帖、点赞、评论、关注、排行榜、私信、审核或社交关系；
- `UNSEEN 官方` 是内容署名，不是假装已经登录的用户账号。

唯一内容源是：

```text
public/official-gallery/v1/official-posts.js
```

媒体全部在同源版本化目录：

```text
public/official-gallery/v1/media/
```

当前三篇帖子覆盖：

1. 照片追问、确认原话并留成一页回忆；
2. DAP 宴会厅受限全景；
3. World Labs 单图补全与 2–8 张同场景多图重建。

自有 3DGS 不作为已开放帖子或可执行入口。它只在 World Labs 案例限制项中标为「训练链路仍在进行中」。

## 2. v1 公开字段合同

`official-posts.js` 导出：

| 导出 | 含义 |
|---|---|
| `OFFICIAL_GALLERY_SCHEMA_VERSION` | 当前公开内容结构版本，v1 为 `1.0.0` |
| `OFFICIAL_GALLERY_AUTHOR` | 唯一官方作者对象 |
| `OFFICIAL_POSTS` | 已发布案例的只读数组 |
| `getOfficialPost(idOrSlug)` | 供详情页按稳定 id 或 slug 查找 |

作者合同：

| 字段 | v1 规则 |
|---|---|
| `id` | 永久稳定的 `unseen-official` |
| `name` / `displayName` | 固定为 `UNSEEN 官方` |
| `kind` | 固定为 `official`；不表示登录态 |

帖子合同：

| 字段 | 类型 | 规则 |
|---|---|---|
| `schemaVersion` | string | 与顶层 schema 版本一致 |
| `id` | string | 永久主键；迁移后台时不可重生成 |
| `slug` | string | 稳定的人类可读定位符；改标题不改 slug |
| `authorId` | string | v1 只能是 `unseen-official` |
| `publishedAt` | ISO 8601 string | 首次公开时间；后台迁移后保留原值 |
| `updatedAt` | ISO 8601 string | 内容最后更新时间 |
| `source` | object | 案例级来源、可审计 provenance 与许可边界 |
| `title` | string | 案例标题，纯文本 |
| `dek` | string | 列表与详情首屏摘要，纯文本 |
| `body` | string[] | 有顺序的正文段落；不存 HTML |
| `capability` | object | 真实能力 id、名称、状态、状态文案与摘要 |
| `media` | object[] | 有顺序的本地媒体及其尺寸、替代文本和来源 |
| `limitations` | string[] | 必须展示的限制与非能力边界 |
| `facts` | `{label,value}[]` | 详情页可扫描的事实对 |
| `viewer` | object \| null | 只读查看入口；v1 仅 DAP 有值 |

`capability` 合同：

| 字段 | 说明 |
|---|---|
| `id` | 稳定能力 id，不使用供应商营销标题代替主键 |
| `label` | 面向用户的能力名称 |
| `status` | 机器可读状态；当前已接能力为 `available` |
| `statusLabel` | 面向用户的诚实状态文案 |
| `summary` | 一句话说明真实输入、处理或结果 |

`source` 合同中的 `label`、`provenance`、`license` 都必须是可展示纯文本。它描述整篇案例的证据来源；逐张素材仍由 `media[*]` 保存更细的 credit 与 license。

`media` 合同：

| 字段 | 说明 |
|---|---|
| `id` | 帖子内稳定媒体 id |
| `kind` | v1 为 `image` |
| `src` | 详情媒体的同源版本化绝对路径 |
| `thumbnailSrc` | 案例流缩略图的同源版本化绝对路径 |
| `width` / `height` | 详情媒体固有尺寸，必须用于预留布局 |
| `thumbnailWidth` / `thumbnailHeight` | 缩略图固有尺寸，必须用于预留布局 |
| `alt` | 描述画面的替代文本；不塞版权或营销语 |
| `credit` | 作者、项目或派生来源 |
| `license` | 当前素材的许可边界；不推断未被证明的开放许可 |
| `sourceLabel` | UI 可展示、审计可追溯的来源说明 |

`viewer` 不是任意 CTA。v1 只允许：

```js
{
  kind: "read-only",
  href: "/unseen-dap?scene=ballroom&back=unseen-demo%3Fcase%3Ddap-ballroom-limited-panorama",
  label: "进入只读 DAP 范例"
}
```

照片回忆与 World Labs 帖子的 `viewer` 都是 `null`。这能避免把案例媒体误传给创作主链。未来若增加 viewer 类型，应先建立显式 allowlist，不允许内容数据直接声明写入 IndexedDB、调用生成 API 或构造外部脚本。

案例详情使用 `/unseen-demo?case=<stable-id>` 作为可恢复 URL。进入 DAP 后，浏览器返回与查看器内返回链接都应恢复原案例，而不是丢回启动页；这个 URL 状态只描述只读展品，不保存个人照片或生成任务。

## 3. 内容与个人数据的硬边界

官方案例数据和个人创作数据必须维持两条不相交的链：

```text
OFFICIAL_POSTS ──> 看看列表 / 案例详情 / 只读 DAP viewer

用户拍摄或选图 ──> state.photo ──> 看图提问 ──> 一页回忆 ──> huijian IndexedDB
                                      └──────────> World Labs 明示同意后的 handoff
```

实现约束：

- 不得把 `post.media[*]`、`thumbnailSrc` 或 `src` 赋给创作状态中的 `state.photo`；
- 不得从案例按钮调用 `saveMemory`、`saveWorldHandoff` 或 World Labs 生成 API；
- 不得为案例生成 `demo:*` 个人照片 id；
- 不得把官方帖子写入 `huijian` 数据库的 `memories`、`collections` 或 `styleProfiles`；
- 不得把官方帖子写入 `huijian-world-lab/source-sets` 的 `latest` 或 `unseen-handoff`；
- 打开 DAP 案例只发生页面导航，不保存一张“当前照片”作为返回快照；
- 如详情页将来提供「用自己的照片体验」，它只能打开空的拍照/选图入口，不能预填案例素材。

旧版本曾允许保存内置例图。迁移时不能删除用户浏览器里的旧记录，但「我的」应过滤 `photos[0].id` 以 `demo:` 开头的旧演示记录；旧 `spatial-return` 中 `source` 为「内置例图」或照片带内置 `file` 的记录也不应恢复为个人创作。

## 4. 能力事实合同

### 4.1 照片追问与一页回忆

- 输入必须来自用户自己的本机照片；
- 只有进入「聊聊这张」才把预览副本交给看图服务；
- MiniMax 读取本机照片生成的清晰预览副本后只问一次；不可靠时明确使用备用开放问题；
- 语音是用户主动开始与停止的转写，文字仍可修改；
- 结果保留确认原话，不自动润色或补写故事；
- 只有用户点击保存才写入当前浏览器 IndexedDB；没有账号或云同步。

### 4.2 DAP 宴会厅

- 真实载荷为 4096×2048 全景、1024×512 深度图和 DAP 查看器；
- 支持 360° 环视与约 0.42 米受限视差；
- 不是自由行走的完整 3D；
- 全景署名为 Sergej Majboroda，Poly Haven CC0；
- DAP 深度模型为 Insta360 Research 的 CC BY-NC 4.0；正式商用可能需要授权或替换模型。

### 4.3 World Labs Marble

- 单图模式是以照片为依据的画外补全，结果包含模型想象；
- 多图模式需要 2–8 张同场景且有重叠的照片，经 Auto Layout 重建共同空间；
- 生成由 World Labs 完成，世界可通过公开链接访问；
- 输入可能按 World Labs 服务条款用于改进模型；
- 生成消耗公共体验额度，通常需要约 5 分钟；
- Marble 当前不返回每张照片的精确相机位姿，照片入口不是精确空间锚点；
- 本帖不展示或暗示自有 3DGS 已开放。

## 5. 媒体来源与派生记录

所有官方案例媒体均为仓内现有素材的本地派生，不使用外部图片热链。

| 输出 | 派生源 | 说明 |
|---|---|---|
| `memory-page-cover.webp` / `memory-page-thumb.webp` | `photos/photo4_table_detail.jpg` | UNSEEN AI 模板图；git commit `8580998` 首次收录；非真人照片 |
| `dap-ballroom-cover.webp` / `dap-ballroom-thumb.webp` | `public/unseen-dap/v1/assets/ballroom-preview.jpg` | 仓内已验收 DAP 截图；全景 Poly Haven CC0，深度 DAP CC BY-NC 4.0 |
| `world-single-cover.webp` / `world-single-thumb.webp` | `photos/photo1_cheers.jpg` | UNSEEN AI 模板图；只表示单图输入，不冒充 World Labs 输出 |
| `world-multi-cover.webp` / `world-multi-thumb.webp` | `photo2_cake.jpg`、`photo4_table_detail.jpg`、`photo3_group_back.jpg` | 三联画只表示多图输入概念，不声称是精确同位姿数据或 canary 输出 |

生成规格：

- 详情媒体：1200×750 WebP，去除元数据；
- 列表缩略图：640×400 WebP，去除元数据；
- 每个 `img` 应输出固有 `width` 与 `height`；
- 列表非首屏媒体使用 `loading="lazy"` 和 `decoding="async"`；
- 详情只在打开对应案例后挂载 `src`，不要把全部详情图藏在 CSS 背景或不可见 DOM 中预载。

仓库 README 记录 World Labs 已以公开 11 视角城堡样例完成单图与多图 canary，但本仓未保存一套许可边界足够清楚、适合再发布的原图和输出。因此 v1 没有复制 Sceaux 等版权不明素材，也没有把输入示意伪装成真实生成结果。

## 6. 缓存与资源路径

`/official-gallery/v1/` 是不可变的公开资源命名空间。v1 内文件一旦发布，不在原路径覆盖不同内容；内容变化时新增 `v2` 或使用内容哈希文件名。

- HTML 保持可更新，不使用一年 immutable；
- `/official-gallery/v1/*` 可使用 `public, max-age=31536000, immutable` 与 ETag；
- 个人 data URL、IndexedDB 数据、World Labs 动态 API、MiniMax API 和错误响应不得继承公共长期缓存；
- 「看看」未打开时，不加载官方案例媒体；
- 拍照、选图、对话、「我的」等个人流程不引用官方案例媒体；
- DAP 高质量载荷只在进入 DAP viewer 后请求，第二次进入通过版本化缓存复用。

## 7. 迁移到官方发布后台

后台迁移必须保留公开字段合同，而不是让 UI 直接依赖某个 CMS 数据形状。

推荐把读取边界保持为两个方法：

```js
listOfficialPosts()
getOfficialPost(idOrSlug)
```

当前实现由版本控制模块返回数据；未来实现可以从同源只读 API 返回相同 DTO：

```text
GET /api/official-gallery/v1/posts
GET /api/official-gallery/v1/posts/:id-or-slug
```

迁移步骤：

1. 将 `OFFICIAL_GALLERY_AUTHOR` 导入后台作者表，保留 `unseen-official` 主键；
2. 将三篇帖子原样导入，保留 `id`、`slug`、`publishedAt` 与媒体路径；
3. 后台可增加内部字段，例如 `draft`、`reviewedBy`、`scheduledAt` 和修订记录，但公开 DTO 仍只输出本文件定义的字段；
4. 发布器负责校验唯一官方作者、能力状态、必填限制、同源媒体、尺寸、来源与许可；
5. 先让 API 与静态模块同时通过同一合同测试，再把读取适配器切到 API；
6. 迁移完成前保留静态 v1 作为回滚与审计快照。

这一步只需要一个受控的官方发布者后台，不需要先建设普通用户账号体系。官方后台的登录、权限和审计日志属于内部运营面，不应在消费者界面伪装成「Max 已登录」或开放注册。

## 8. 发布器必须拒绝的内容

未来发布器遇到以下任一情况应拒绝发布：

- `authorId` 不是 `unseen-official`；
- `id` 或 `slug` 与已有帖子冲突；
- 媒体是外部热链、缺固有尺寸、缺 alt、缺 credit 或缺 license；
- 把 DAP 描述成自由行走完整 3D；
- 缺少 DAP CC BY-NC 4.0 与商业授权说明；
- 缺少 World Labs 第三方处理、公开链接、模型改进可能性、额度或非精确锚点说明；
- 把自有 3DGS 标为 `available`；
- `viewer` 声明写入个人存储、预填案例图、自动提交或任意脚本；
- 正文暗示点赞、评论、关注、排行榜或用户公开发帖已经存在。

## 9. v1 非目标

本轮明确不实现：

- 官方账号登录页或伪登录状态；
- CMS、数据库、上传面板和内容审核工作台；
- 普通用户注册或公开发帖；
- 点赞、评论、关注、排行榜、私信与社交图谱；
- 把官方案例复制为个人照片、回忆或 World Labs 任务；
- 接入或展示已开放的自有 3DGS。

这些边界保证第一版先成为可信、克制、可审计的官方案例馆，同时为以后接入真正的官方发布后台保留稳定数据合同。
