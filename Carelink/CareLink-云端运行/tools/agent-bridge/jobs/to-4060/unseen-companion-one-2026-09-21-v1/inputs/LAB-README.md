# UNSEEN × Companion One：桌面空间窗口 v0.1

方向建议：**电脑计算，C1 作为空间呈现端；先做小而浅的静态空间窗口，再接一份真实 UNSEEN 场景。** Max 已确认可使用 Windows 电脑。树莓派、独立主机和外壳不进入这一阶段。

目前交付的是可运行的内容测试台和实验接屏适配。**硬件尚未到货，真实校准文件尚未取得，不能声称接屏或肉眼 3D 已通过。** Mac 已做内容开发和浏览器验证；首个官方支持的接屏环境采用 Windows 10/11。

## 现在就可以运行

这个 Mac 上：双击 `start-mac.command`，在 Chrome 打开 **http://127.0.0.1:4717**。

Windows：把整个发布包复制过去并解压，安装 Node.js 22 或更新版本，双击 `start-windows.cmd`，在 Chrome / Edge 打开同一地址。发布包带运行依赖，不需要执行 npm install；初次下载源代码才需要：

```sh
npm ci --omit=dev --ignore-scripts
npm start
```

保持终端窗口打开；Ctrl+C 停止。程序只监听本机 127.0.0.1，不访问云端、不上传模型或校准文件。模型及校准只保留在当前页面内存中，刷新后需要重选。运行端不需要 Blender 或 Unity。

## 已实现

- **标准内容**：窗边小景；前方竖条 / 后方球与圆环的遮挡测试。
- **真实多视角**：平行相机平移与离轴投影，焦平面固定；可调整观察位置、场景深度和相机跨度，不靠物体自转模拟视差。
- **自有内容**：自包含 GLB 文件（100 MB 以内）；自动居中和缩放。外部资源引用会拒绝。动画暂时显示静态姿态；未配 Draco / KTX / Meshopt 解码器的压缩模型请重新导出普通 GLB。
- **Quilt 导出**：40 个独立视角，8 列 × 5 行，每格 540 × 960，总尺寸 4320 × 4800 PNG；视图 0 从图像左上角开始，逐行排列，沿用官方 Blender 的相机/网格约定。
- **实验接屏**：导入自己的 `deviceConfig.json`，本机解析官方文件格式，使用公开 SDK 算法进行 RGB 子像素交织。无参数或全屏尺寸不符时停止输出。参数载入不等于设备自动识别或光学验收。
- **测试记录**：人工勾选结果并导出 JSON；未勾选保留 `not-confirmed`，不自动算失败或成功。

不包含：3DGS 导入、普通照片自动重建、UNSEEN 生产接口、视频播放器、完整房间漫游、自动设备检测、独立离线硬件。这些不是本阶段接屏验样的前提。

## 硬件到货后的步骤

1. **先跑厂商基线。** 在 Windows 10/11 安装 [CubeStage](https://cubevi.com/pages/download-page)。按随箱说明接好 HDMI 视频与 Type-C 所需连接/供电，使用扩展显示，确认官方样例有正常的立体效果。接口形态和是否支持单线以收到版本的说明为准。
2. **核对主机。** [官网 C1 FAQ](https://cubevi.com/products/cube-c1) 目前列桌面 GPU 基线 GTX 1660 / RX 580；对笔记本另列独显、MUX/独显直连要求。这是厂商对现成软件的要求；本项目未对 Windows GPU 做过性能测量。不要把“HDMI 已点亮”算成官方 3D 样例通过。
3. **取自己的参数。** CubeStage 正常识别屏幕后，查找 `%APPDATA%\Cubestage\deviceConfig.json`，旧版本为 `%APPDATA%\OpenstageAI\deviceConfig.json`。在测试台展开“校准与接屏”，导入该文件。新版本若改变路径或格式，记录现象再适配；不要填示例参数凑通。
4. **配置像素映射。** 显示器设 1440 × 2560 竖屏、建议 100% 系统缩放、浏览器 Ctrl+0 恢复 100% 缩放。检查显卡/显示器无缩放拉伸。将测试台窗口拖到 C1。
5. **开始实验输出。** 点击“在 C1 全屏”。软件核对浏览器可用像素；通过后才交织输出。浏览器无法证明 EDID、操作系统合成和物理像素实际一一对应，仍要对照系统原生分辨率。Esc 返回。
6. **观察固定场景。** 屏幕不动，在约 50–80 cm 处左右移动头部：前面的竖条应相对后面的球/圆环移动，露出原先遮住的部分。不能把所有人都看见同一个自转视频当成通过。条件允许时，两人从不同水平位置同时观察。
7. **记录问题。** 优先看焦平面附近是否清晰、深度是否反转、是否重影、视区是否太窄。只有官方样例正常而我们的深度颠倒时，才试“反转视序”。记录和导出结果；刷新页面会清空未导出的记录。

如果官方样例不正常，先处理连接/显卡/厂商校准。如果官方正常、测试台不正常，问题收敛在自研交织器、视序、色彩或系统像素映射。**Windows 官方路径已确认存在，但这个自研播放器仍是待实机测试的移植。**

## 推荐的研发顺序

| 阶段 | 真正要验证的事情 | 通过之后 |
|---|---|---|
| 到货当天 | 标准几何场景能产生稳定水平视差、合理遮挡和可接受清晰度 | 接一份自己的真实内容 |
| 真实记忆窗口 | 一个熟悉角落/物件，在小屏里是否比普通照片更有空间感 | 决定内容生成与展示形态 |
| UNSEEN 内容接入 | 使用现有静态重建资产；3DGS 先考虑离线渲染 Quilt，再评估实时多视角成本 | 才加入声音、切换记忆和交互 |

前两步都不需要树莓派。5.7 英寸屏的标称可视分辨率约 540×960、景深约 6 cm，适合用小窗呈现浅空间。先避免大量小字 UI 或巨大房间实时漫游；这些是本项目的选择，不是对设备能力的实测结论。

## 证据与验证

- 当前产品与接口：[官方 C1 页面](https://cubevi.com/products/cube-c1)。Windows-only；40 视图；规格为厂商标称。
- 官方开发：[Blender SDK](https://github.com/CubeVi/CubeVi-Swizzle-Blender)、[Unity SDK](https://github.com/CubeVi/CubeVi-Swizzle-Unity)。本项目参考 C1 SDK，未把 PLAY 新型号 API 套给 C1。
- 逐项记录与访问限制：[research/quick.md](research/quick.md)。
- 本地测试：`npm test` 和 `npm run test:browser`。浏览器测试使用本 Mac 安装的 Chrome；其他机器可通过 `COMPANION_CHROME` 指定浏览器可执行文件。测试包含合成参数；它们不是可用于设备的校准值。
- 测试证据：[VALIDATION.md](VALIDATION.md)。
