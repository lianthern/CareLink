## 执行顺序与续跑

- 复用 `D:\H3-runtime` 和安装任务通过的入口。只建独立 `D:\H3-runtime\projects\unseen-full-v1` 工作/输出目录，不重装 H3、不重复下载权重。
- 安装最终验收发现一个真实的长流程缺口：`run_service.py` 启动后只等 H3 子进程，没有监测持有 GPU 共享锁的 guard 提前退出。正式排队前，保留原脚本副本，补上 guard 存活监督；失锁即停止属于本次已核身份的 H3 子进程树并记录退出，不能让推理失去锁后继续。先以本次独立测试进程验证 guard 正常退出/异常退出/子进程回收，再以原共享锁入口启动；测试不能触碰旧 3DGS 进程或假冒安装已具备此保护。具体入口及证据见 `4060-REUSE-AND-PRIVATE-BRIDGE.md`。
- 先验证现有图像条件节点及输入路径。中性文字生视频成功不等于参考图条件已经验证。选择工作流实际支持的首帧/参考图条件，不能悄悄退为各镜头无参考的独立随机人物；一条短 clip 即可同时验证参考输入和 H01。
- 看完参考后冻结人物与三处空间。用既有本地能力调整必要参考；若缺少合格反打，可利用同场景其他参考和连续的较紧构图生成，禁止将孩子从站立改成坐下以迁就旧图。图片能力/节点不可用时先报告具体缺项，不调用收费平台。
- 顺序队列：H01 → H02 → 检查两镜连贯 → H 系列其余镜头 → S 系列 → W 系列 → E 系列。每次只有一个 GPU 生成任务。每镜保留约 0.3—0.5 秒可剪余量，实际可用长度记录下来。
- 每个镜头最初一次 + 最多两次有针对性的修订。失败时说明具体画面错误再改单一因素；不要盲换 seed 无限重跑。到达此上限可采用更简单但仍有真实动作且保留故事目的的覆盖镜头；两种方案均不可用时保留失败状态并继续独立镜头，不用坏片或静帧补齐冒充完整通过。

- 每完成一镜：原片落盘 → decode → 抽帧/视觉检查 → 状态写盘 → 继续下一镜。中断后按 manifest 和 hash 跳过合格原片。阶段报告按“家完成 / 学校完成 / 婚礼完成 / 成片待验 / 真实阻塞”发，不逐帧刷屏。
