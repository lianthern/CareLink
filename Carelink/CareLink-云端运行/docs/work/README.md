# 项目工作记录

每项任务建立一份 `YYYY-MM-DD-short-name.md`，并用分支和 PR 关联代码。多设备、多 Agent 不共用同一份可写 checkout；同一任务由一个负责人汇总。实验可以失败，但应留下结论和对应版本。

寻找过去的草稿、实验或原素材，从 [UNSEEN 总档案](../../ARCHIVE.md) 进入。新产物不会自动进入已有日期快照；任务记录要写明它目前只是本机文件，还是已经得到远端归档校验回执。

复制以下模板：

```md
# 任务名称
日期：
负责人 / Agent：
分支 / 提交 / PR：
目标：
涉及目录：
当前状态：进行中 / 待验证 / 已完成 / 暂停

## 结果与决策
做了什么，观察到什么，还缺什么。

## 验证
检查命令、结果和必要的证据链接。区分本地测试、实机验收和已部署。

## 产物
代码路径、文档、演示链接。大文件另记大小、SHA256、存放位置和访问方式。
旧稿与失败实验：保留位置、来源版本。
远端归档：快照日期 / 文件 ID / 校验回执；未上传时明确写“仅本机”。

## 下一步
可直接继续的具体事项。
```

短文档、脚本、测试和小型实验结论直接进 Git。可重新生成的输出放 `.local/`，重要大产物先保存到可靠位置，再记录清单。原素材和数据库需要独立备份；只有清单没有文件，不算备份。
