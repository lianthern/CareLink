## 2. 当前正式产品边界

本阶段是“上传优先”的多人记忆空间，不在正式产品里提供全景拍摄或本地拼接：

1. 用户创建一个记忆空间，或通过空间链接进入已有空间。
2. 参与者从系统相册上传已经拍好的普通照片。
3. 照片进入该空间的时间轴，参与者共同补全同一天的记忆。
4. 创建者可选上传外部全景相机或第三方软件已经制作完成的 2:1 等距柱状全景图。
5. 全景图只接受 JPEG、PNG、WebP，最大 50 MB，最小 1600×800，宽高比 1.90–2.10；不接受 HEIC/HEIF。
6. 成品全景默认先显示常驻 2D 图片；360° WebGL 仅由用户主动开启，任何初始化、渲染或 context lost 失败都必须立即回到 2D。
7. 正式创建/上传流程不提供相机拍全景、自动拍照、视频扫拍、陀螺仪引导或本地拼接；允许长期保留一个与正式流程隔离的 `/demo` 演示中心。演示中心的技术实验只使用本地 mock/只读说明，不写 Supabase、不上传 Storage，也不得重新接回旧相机或拼接深链。
8. 当前为 bearer-link MVP：拿到空间链接即可查看和贡献。UI 不得声称真正的私密空间、成员权限或登录账号。

## 3. 固定交互流程

### 普通照片

`首页 → 创建/打开空间 → 空间详情 → 上传照片 → 相册选择（最多 9 张）→ 处理中 → 上传中 → 保存中 → 完成/失败 → 只重试失败项 → 时间轴刷新`

- 单张最大 20 MB；大图在客户端压缩到最大边约 2560、质量约 0.82。
- HEIC/HEIF 按扩展名、MIME 与 ISO-BMFF 文件头共同识别，并提示先导出 JPEG。
- 每个选择项只生成一次稳定 `clientUploadId`；重试沿用同一路径。
- 连续双击只允许启动一轮上传；done 项永不重复上传；全部状态都占 9 张上限。
- Storage 409 与数据库 23505 必须按幂等成功路径恢复。
- 上传中禁用添加、删除、重试、完成与离开；卸载后不得继续 setState，所有 object URL 必须释放。

### 成品全景

`创建空间详情 → 选择外部成品 2:1 全景 → 本地严格校验 → 上传原文件 → 保存空间 → 2D 查看 → 用户可选开启 360°`

- 页面明确写明“UNSEEN 当前不提供拍摄或拼接”。
- 不压缩成品全景，不把 20–50 MB 全景转 Base64 发给 AI。
- 用户选择了封面或全景后，对应上传返回空值或报错必须中止创建，绝不能创建缺素材空间。
- 2D 图片始终是安全底层；只有 WebGL 第一帧真实成功后才显示 360 覆盖层。
