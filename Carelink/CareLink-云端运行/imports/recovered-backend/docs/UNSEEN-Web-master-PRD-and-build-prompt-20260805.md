# UNSEEN 网页端总 PRD / 一次性建站提示词

> 用途：把本文件从“开始复制”到“复制结束”整体粘贴给任意 AI 建站平台。  
> 目标：即使模型能力一般，也能做出一个功能完整、边界清楚、可验收的 UNSEEN 网页版，而不是只有好看首页的空壳。

---

## 开始复制

你是一名资深产品经理、UI/UX 设计师和全栈工程师。请直接设计并实现一个可运行、可部署、移动端优先且桌面端可用的 Web 产品，名称为 **UNSEEN**。

不要只输出方案、伪代码或静态效果图；请实际创建页面、路由、组件、数据表、文件上传、错误状态和演示数据，并自行完成响应式与核心流程测试。不要反复向我询问小问题；缺少非关键素材时使用统一风格的高质量占位素材继续完成，但不允许出现空白卡片、失效按钮或破图。

如果当前平台支持 React、TypeScript、数据库、对象存储和 Serverless/Edge Function，优先使用这些能力；如果平台技术栈固定，则用平台原生能力实现同等效果。默认推荐：**React + TypeScript + Vite + CSS Variables/Tailwind + Supabase 或平台内置数据库与对象存储**。

### 1. 产品定义

UNSEEN 是一个“多人共同补全同一天”的记忆空间：

- 创建者建立一个婚礼、旅行、聚会或日常记忆空间，并分享一个链接。
- 参与者无需下载 App、无需注册账号，打开链接后即可查看空间并从手机相册上传普通照片。
- 来自不同人的照片汇入同一条时间线，让原本散落在多台手机里的同一天重新聚在一起。
- 创建者可选上传一张由外部全景相机或第三方软件制作好的 2:1 等距柱状全景图。
- 全景默认以稳定的 2D 图片展示；只有用户主动点击后，才进入 360° WebGL 增强模式。任何 WebGL 失败都必须自动回到 2D，不能黑屏。

核心价值文案固定为：

> 把散落在每个人手机里的那一天，放回一起。

这是一个 **upload-first（上传优先）MVP**，不是相机应用。

### 2. 不得违反的产品边界

以下规则优先级最高：

1. 正式产品不提供拍摄全景、视频扫拍、自动拍照、陀螺仪采集、本地拼接或 AI 拼接。
2. 不要创建“拍摄”“拼接”“Studio”“Roadshow”“AI 重建”“DAP”“Replay”“Profile”“会员”或“退出登录”等虚假入口。
3. 当前没有账号系统、成员权限或真正私密空间。它是 bearer-link MVP：拿到链接的人可以查看并贡献。
4. 可以让访客填写可选昵称，但昵称只是显示名称，不是身份认证；未填写时显示“匿名参与者”。
5. 不得声称“仅受邀可见”“端到端加密”“只有成员能看”或“AI 已精确还原拍摄位置”。
6. “TA 的视角”“AI 档案馆”等内容属于清楚标注的产品 Demo，不得伪装为当前正式生产能力。
7. 正式流程的任何上传失败都不能假装成功，也不能静默创建缺少已选素材的空空间。

### 3. 实现优先级

严格按以下顺序完成。P0 全部通过后再完善 P1，但最终交付必须包含两层。

- **P0 正式产品**：首页、创建/加入空间、空间列表、空间详情、普通照片上传、时间线、分享、外部成品全景、2D/360° 安全查看、本机草稿。
- **P1 产品演示**：演示中心、理想成品、六幕产品故事、AI 演示档案馆与其完整子页面。
- **P2 体验完善**：加载骨架、空状态、键盘操作、减少动态效果、断网/超时提示、桌面布局、无障碍和自动测试。

禁止先做大段营销动画，最后留下不可用的上传按钮。

### 4. 信息架构与路由

实现以下路由。可以按框架语法调整，但页面关系和返回路径必须一致。

#### 正式产品

- `/`：首页
- `/spaces`：这台设备打开过的共享空间 + 本机草稿
- `/create`：创建空间
- `/join`：粘贴邀请链接或空间编号
- `/space/:spaceId`：空间详情
- `/space/:spaceId/upload`：上传普通照片
- `/space/:spaceId/panorama`：成品全景查看

#### 演示内容

- `/demo`：演示中心
- `/demo/vision`：理想的共同记忆空间
- `/demo/story/:scene`：六幕产品故事，scene 为 1–6
- `/demo/archive`：AI 演示档案馆
- `/demo/archive/ai-wedding`：一场未曾拍摄的婚礼，四幕 AI 全景
- `/demo/archive/reference/:id`：四个真实全景技术样片
- `/demo/archive/mode/:id`：五种观看形态
- `/demo/archive/history/:id`：五份历史概念稿

未知路由跳回 `/`，旧的拍摄/拼接/Studio/Profile 等深链也统一跳回 `/`，不得留下可访问的死页面。

全局返回链固定：

`详情页 → AI 演示档案馆 → 演示中心 → 首页`

### 5. 全局导航

正式产品底部导航只有三项：

1. 首页
2. 空间
3. 创建

Header 左侧为 UNSEEN 品牌，右侧只保留一个“◇ 演示”入口。二级页显示返回按钮和页面标题。

不要添加第四、第五个拥挤入口。上传正在进行时，返回按钮、底栏跳转和浏览器离页都应被暂时阻止，并提示“请等待当前上传完成”。

### 6. 页面级需求

#### 6.1 首页 `/`

从上到下依次为：

1. Header：U 图形标记、UNSEEN、右侧“◇ 演示”。
2. Hero：
   - 小标题：`SHARED MEMORY SPACE`
   - 主标题：`把散落在每个人手机里的那一天，放回一起。`
   - 说明：`创建或加入空间，上传普通照片与已经制作完成的 2:1 全景图。`
   - 标签：`上传优先 MVP`
3. 场景选择：婚礼、旅行、聚会、日常，2×2 卡片。默认选中婚礼；点击只改变选中态并预填创建页，不执行提交。
4. 主按钮：`创建一个记忆空间 →`
5. 次按钮：`通过邀请链接加入`
6. 演示 Banner：进入 `/demo`。
7. 如果本机有记录，显示最近 3 个共享空间和最近 3 个本机草稿。

所有卡片必须能点击进入真实页面，不能用 alert 冒充页面。

#### 6.2 空间列表 `/spaces`

分两组：

- 共享空间：这台设备曾创建或打开过的空间，显示标题、日期/编号、是否为创建者。
- 本机草稿：只存在 IndexedDB/平台本地数据库中的草稿，显示标题、照片数和缩略图。

提供“创建共享空间”和“打开已有空间”。

允许删除本机草稿，删除前二次确认；不要允许访客从这里删除云端空间。

#### 6.3 创建空间 `/create`

字段：

- 空间名称，必填，1–60 字。
- 场景：婚礼 / 旅行 / 聚会 / 日常。
- 日期，可选。
- 地点，可选，最多 80 字。
- 一句话说明，可选，最多 120 字。
- 封面，可选，JPEG/PNG/WebP，最大 20 MB。
- 成品全景图，可选。

全景区域必须明确显示：

> 仅上传外部全景相机或第三方软件已制作完成的 2:1 全景图；UNSEEN 当前不提供拍摄或拼接。

全景规则：

- 只接受 JPEG、PNG、WebP。
- 不接受 HEIC/HEIF。
- 最大 50 MB。
- 最小 1600×800。
- 最大 8192×4096。
- 宽高比必须在 1.90–2.10。
- 保留原文件，不压缩，不转 Base64。
- 在上传前读取真实尺寸并校验；失败时显示具体原因并阻断创建。
- 更换或移除图片时释放旧的 object URL，避免内存泄漏。

提供两个明确动作：

- 主按钮：`创建共享空间`
- 次按钮：`仅保存在本机`

共享空间创建流程必须是：

`校验表单 → 创建幂等空间草稿 → 上传已选封面/全景 → 服务端复核文件 → 发布空间 → 进入空间详情`

要求：

- 按下按钮后同步加锁，连续双击只启动一次。
- 状态依次显示“正在创建空间 / 正在上传封面 / 正在上传成品全景 / 正在发布空间”。
- 如果用户选过封面或全景，对应上传返回空值、报错或服务端校验失败时，立即停止，不得发布缺素材空间。
- 失败后保留表单和已选文件，可使用同一幂等 ID 安全重试。
- 云端失败不能自动降级成“本机成功”。

本机草稿保存在 IndexedDB；媒体保存为 Blob，不上传云端。创建成功后进入同样的空间详情页，并明显标记“本机保存”。

#### 6.4 加入空间 `/join`

一个输入框，接受：

- 完整邀请链接；或
- 纯空间编号。

提交后解析出 spaceId 并进入空间详情。格式无效时在输入框附近显示具体错误，不清空用户输入。

页面说明：

> 这是链接访问型 MVP。拿到链接的人可以查看并贡献；它不是账号或成员权限系统。

正式环境只允许打开本站受信任域名/存储中的空间，不能让邀请链接覆盖 API 或对象存储地址。

#### 6.5 空间详情 `/space/:spaceId`

页面从上到下：

1. 封面区：图片、空间名、日期和地点。无封面时使用品牌渐变，不显示破图。
2. 状态提示：云端空间 / 本机草稿 / 上传通道过期或空间已满。
3. 统计卡：照片数、贡献者数、成品全景数。
4. 主按钮：`上传普通照片`。
5. 有全景时显示：`查看 2D 全景`；没有时不要显示假入口。
6. 云端空间显示：`分享邀请链接`；本机草稿显示：`导出发布配置`。
7. 照片时间轴：按 `capturedAt` 倒序；没有 capturedAt 时按 `createdAt` 倒序。
8. 空状态：`空间里还没有照片，上传后会从这里开始共同补全。`

点击时间轴照片后打开全屏灯箱，支持上一张、下一张、关闭、Escape 和左右滑动；灯箱打开时锁定背景滚动。

上传通道关闭、过期或容量已满时禁用上传按钮，并显示具体原因；不能一直显示 loading。

分享逻辑：

1. 优先调用 `navigator.share`。
2. 用户主动取消时不报错。
3. 其他失败继续尝试 Clipboard。
4. Clipboard 不可用时弹出真实可选择、可复制的当前 URL。
5. 只有实际成功时才显示“邀请链接已复制”。

分享链接只含公开 spaceId，不得包含 hostKey、管理员 token、数据库密钥或可写路径。

#### 6.6 普通照片上传 `/space/:spaceId/upload`

允许从系统相册一次选择多张普通照片，每一批队列最多 9 项。

文件规则：

- JPEG、PNG、WebP。
- 单张最大 20 MB。
- HEIC/HEIF 必须通过扩展名、MIME 和 ISO-BMFF 文件头共同识别；命中任一条件即阻断并提示先导出 JPEG。
- 大图在浏览器本地压缩到最大边约 2560 px、JPEG/WebP 质量约 0.82。
- 小图可保留原尺寸；压缩失败可以回退原图，但最终文件仍必须小于等于 20 MB。
- EXIF 拍摄时间是可选增强，解析失败不能阻断上传。

队列要求：

- pending、processing、uploading、saving、done、error 全都占 9 张上限。
- 每个文件在“被选中时”生成一次稳定 `clientUploadId`；重试沿用同一 ID，不得重新生成。
- 行内显示文件名、大小、状态、进度和具体错误。
- 状态文案固定：`待处理 / 处理中 / 上传中 xx% / 保存中 / 已上传 / 失败`。
- 上传开始前可移除；上传中禁用添加、移除、重试、完成和离开。
- 连续双击上传只能产生一轮请求。
- `只重试失败项` 只处理可重试的 error 项；done 项永不重复上传。
- 全部完成后显示 `完成并返回空间`，返回后刷新时间轴。
- 删除项目、离开页面或组件卸载时释放预览 URL、ImageBitmap、Canvas 和监听器；卸载后异步回调不得继续更新页面。

远程上传流程：

`校验 → 本地压缩 → 向服务端申请精确上传票据 → 直传对象存储 → 服务端校验并提交记录 → 刷新公开空间清单`

幂等要求：

- `spaceId + clientUploadId` 必须唯一。
- 重试使用同一个对象键。
- 对象存储返回 409/already exists 时，继续查询/提交同一路径，不创建第二份。
- 数据库唯一键 23505/duplicate 时重新查询原记录并按成功处理。
- 不删除已经成功上传的对象。
- 网络超时、5xx、429 可重试；格式、尺寸、容量满等错误不可重试。

本机草稿使用同一队列 UI，但完成后把压缩 Blob 写入 IndexedDB，不调用云端接口。

#### 6.7 全景查看 `/space/:spaceId/panorama`

默认先渲染完整可见的 2D 等距柱状图片：

- 可拖动查看细节。
- 滑杆、滚轮或双指缩放 1–3 倍（移动端可到 4 倍）。
- 图片加载失败时显示明确错误与重试，不使用黑色空画布。

提供次级按钮：`开启 360° 模式`。只有用户主动点击后才动态加载 Three.js/WebGL。

360° 安全要求：

- 2D `<img>` 始终是可见底层。
- WebGL canvas 是 `position:absolute; inset:0` 的覆盖层。
- 使用低资源配置：`antialias:false`、`powerPreference:'low-power'`、`setPixelRatio(1)`。
- 动态加载、纹理加载、容器尺寸、renderer、首次 render、动画循环、resize、context lost 全部有 try/catch 和统一 cleanup。
- 只有首帧真实 render 成功后，才让 canvas 可见。
- 初始化失败、容器尺寸小于等于 1、纹理失败、render 抛错或 `webglcontextlost` 时，立刻停止 RAF、dispose renderer/texture/material/geometry/controls、移除 canvas 和监听器，然后回到 2D。
- 回退提示：`360° 模式不可用，已回到平面图。`
- 关闭 360、切换路由和组件卸载可重复 cleanup，不能抛错或泄漏。

任何情况下都不能用整页黑屏替换已经可见的 2D 图片。

### 7. 演示中心 `/demo`

演示中心与正式数据完全隔离：不调用相机、不上传 Storage、不写正式数据库。所有内容使用本地/只读演示数据，并醒目标注 `DEMO`、`AI GENERATED` 或“概念体验”。

页面包含：

1. Hero：`从理想成品开始看。`
2. 建议体验顺序：`01 看理想成品 → 02 看六幕故事 → 03 翻 AI 档案`
3. 四个真实可进入的入口：
   - 理想的共同记忆空间
   - 六幕产品故事
   - 上传优先流程（进入正式 `/create`，不自动提交）
   - AI 演示档案馆
4. 说明：演示不会调用相机、不会上传、不会写入正式空间。

不要用 alert、modal 或在卡片下面展开三段文字来冒充完整 Demo。

### 8. 理想成品 `/demo/vision`

这是静态但可操作的产品目标演示，标题示例为“我们的婚礼”，显示日期、地点、12 位朋友、86 张照片、3 个全景。

固定四个 Tab：

1. **空间**：统计、最近参与者头像、刚补进的照片、两段记忆卡片。
2. **时间线**：2 列照片流，至少六个时刻：抵达、交换戒指、台下笑声、举杯、花童跑过、最后合影。
3. **全景**：2:1 宴会厅图片，可切换正前/右侧/后方/左侧；说明正式产品始终先显示 2D。
4. **TA 视角**：至少四位拍摄者，切换后更新照片、方向、时刻和说明，并显示雷达式方向图。

“TA 视角”下面必须写明：这是目标体验 Demo；正式能力需要可靠的相机位姿与图像配准，不能把粗略方向分类冒充精确拍摄位置。

### 9. 六幕产品故事 `/demo/story/:scene`

必须有进度条、`01/06` 计数、圆点导航、上一幕、下一幕；最后一幕按钮为“进入理想成品”。六幕内容固定为：

1. **散落**：那一天被留在很多人的手机里。
2. **归集**：一个链接，不用下载 App，大家上传普通照片和外部成品全景。
3. **空间**：时间线回答“发生了什么”，全景回答“当时我在哪里”。
4. **多视角**：同一时刻，每个人看见不同方向。
5. **共同补全**：哪些时刻或方向仍然空着，一眼可见。
6. **成品**：照片、全景、时间线与每个人的视角构成可分享、可重看的共同记忆。

每一幕都要有独立视觉，不得只是更换一段文字。

### 10. AI 演示档案馆 `/demo/archive`

档案馆不是正式功能清单，而是 UNSEEN 历史概念和视觉演示。页面结构固定为：

#### 主作品：1 项

`一场未曾拍摄的婚礼`

- 明确标注“纯 AI 生成”。
- 四幕：初见（迎宾庭院）、誓言（林间仪式）、共宴（烛光长桌）、尽兴（星夜派对）。
- 每幕有 2:1 全景、标题、地点、说明和场景 Tab。
- 四幕之外再展示 8 张统一风格的 AI 婚礼照片，可点击进入灯箱，并持续标注“AI GENERATED”。
- 2D 模式支持左右无限拖动，使用无缝水平平铺，不能拖出黑边。
- 可选主动开启 360°，失败规则与正式全景查看一致。
- 四幕可完整 `n1 → n2 → n3 → n4 → n1` 循环切换。

#### 技术对照：4 项

- 入口大厅
- 舒适咖啡馆
- 日间礼堂
- 古典宴会厅

每项是可进入的真实全景样片页，用于验证环视、室内尺度、亮暗场和照片钉点。使用自有素材、CC0 素材或平台生成素材，并保留来源说明；不要盗用受限图片。

#### 同一段记忆的五种看法：5 项

- 婚礼旅程：按地点/章节前进。
- 时光轴：按时刻查看多视角照片。
- 记忆相册：传统照片墙与灯箱。
- 机器回忆：显示方向、置信度与“待复核”，明确这是机器视角演示。
- 一键成片：短片负责情绪，结束后可进入空间继续探索；没有视频素材时生成一个可播放的短示例或使用明确的本地占位视频，不留死播放器。

#### 历史原稿：5 项

- 六幕评委 Demo
- 路演现场
- 空间工作台
- 回到 TA 的视角
- 产品 Showcase

每项都进入独立详情页，至少包含：版本标签、原始目标、保留下来的启发、为何不属于当前正式 MVP、返回档案馆按钮。禁止只放一个不可点击标题。

档案馆总计 15 个可进入入口：1 个主作品 + 4 个技术对照 + 5 个观看形态 + 5 个历史原稿。

### 11. 视觉系统

整体气质：温柔、克制、有记忆感，不做婚庆模板的俗艳金色，也不做深色科技仪表盘。正式产品以浅暖粉白为主，档案馆的 AI 主作品可以使用深酒红沉浸区。

固定颜色：

- 桌面外层背景：`#F4EEF0`
- 内容背景：`#FFF9F7`
- 卡片：`#FFFCFB`
- 正文：`#59383E`
- 次级文字：`#94787C`
- 粉色：`#F8C8D6`
- 橙色：`#FDE0A8`
- 激活色：`#FF7F9F`
- 主渐变：`linear-gradient(100deg,#F8C8D6,#FDE0A8)`
- 错误色：偏莓红，不使用刺眼纯红。
- 成功色：柔和墨绿。

字体使用系统无衬线字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Microsoft YaHei", "Segoe UI", sans-serif`。根字号固定 16px，430px 和桌面都不能放大到 18px。

布局规则：

- 手机宽度 100%，最小支持 320px。
- 正式核心流程在桌面使用居中的 `max-width:430px` 内容壳，`min-height:100dvh`。
- 不要添加假手机边框、固定 932px 高度、桌面圆角外壳或设备阴影。
- 大型档案馆/相册页在桌面可扩展到 980–1100px，但手机仍为单列；正式创建和上传流程仍保持 430px 以减少认知负担。
- Header、main、BottomNav 必须属于同一个 flex column；main 为 `flex:1; min-height:0`。
- 卡片圆角 16–26px，触控目标至少 44×44px。
- 所有按钮、链接、输入框有 `:focus-visible`；图片有 alt；颜色对比可读。
- 支持 `prefers-reduced-motion`，关闭非必要动画。

首页在 430×932 视口的参考几何：

- 左右边距 20px。
- Hero 宽 390px、高约 220px。
- 四张场景卡 2×2，每张约 189×81px，间距 12px，圆角 16px。
- 主 CTA 宽 390px、高约 77px。
- 次 CTA 高约 55px。
- 首页核心创建/加入内容尽量在约 819px 前结束。

不要用绝对定位硬钉整页，也不要为了塞进首屏缩小可读字体。

### 12. 数据模型

至少创建以下逻辑模型；字段名可以遵循平台规范，但含义必须保留。

#### Space

```text
id: string, primary key
clientCreateId: string, unique, 创建幂等键
title: string
scene: wedding | travel | party | daily
date: date | null
place: string | null
subtitle: string | null
coverUrl: string | null
panoramaUrl: string | null
status: draft | published | closed
accessType: link
maxPhotos: 90
photoCount: number
createdAt: timestamp
updatedAt: timestamp
```

#### Photo

```text
id: string, primary key
spaceId: string, foreign key
clientUploadId: string
contributor: string, default 匿名参与者
caption: string | null
url: string
thumbnailUrl: string | null
width: number
height: number
capturedAt: timestamp | null
createdAt: timestamp
unique(spaceId, clientUploadId)
```

#### LocalSpace

保存在 IndexedDB，字段与 Space 类似，媒体与照片存 Blob；增加 `localOnly:true`、`updatedAt`。不要把大图放进 localStorage。

#### UploadTicket / Commit

由服务端生成短期、单文件、单对象键的上传票据，并绑定 spaceId、clientUploadId、最大尺寸、允许 MIME 和过期时间。提交成功后生成不可变 Photo 记录。

### 13. 后端与安全

如果平台有后端，请实现统一版本化 API 或等效 Server Action：

- `createSpace`
- `finalizeSpace`
- `getSpace`
- `createPhotoUploadTicket`
- `commitPhoto`

关键要求：

1. 浏览器不能拿到对象存储 Secret、Service Role Key 或可写整个目录的长期密钥。
2. 上传票据有效期建议 15 分钟，只允许一个确定对象键、一个文件、指定大小和 MIME。
3. 服务端在提交前重新读取真实对象，用 magic bytes、实际尺寸和文件大小复核，不能只相信浏览器的扩展名/MIME。
4. 公开空间读取与照片贡献通过链接完成；数据库匿名角色不得拥有宽泛 UPDATE/DELETE。
5. 创建者密钥只保存在本机安全存储或 HTTP-only 机制中，绝不进入分享 URL。
6. 单空间最多 90 张普通照片；达到上限后关闭上传并显示原因。
7. 所有用户文本做长度限制、HTML 转义和控制字符清理。
8. API、上传和图片读取都有 15–90 秒合理超时，并向用户返回中文错误。
9. CORS 只允许正式 Web 域名；正式页面不接受邀请链接指定任意 API/Storage Host。
10. 如果平台暂时无法实现安全后端，必须把应用明确标成“本地 Demo”，使用 mock 数据完成 UI；绝不能把 secret 写进前端来假装云端可用。

### 14. 演示数据与素材

必须内置一套完整演示数据，保证第一次打开不是空白：

- 示例空间：`我们的婚礼`
- 日期地点：`2026.10.06 · Brisbane`
- 12 位参与者、86 张照片、3 个全景的统计展示。
- 至少 12 张统一婚礼主题照片。
- 至少 1 张可用的 2:1 宴会厅全景。
- AI 婚礼四幕各 1 张 2:1 全景。
- 技术对照四个场景各 1 张全景和 3 张局部照片。

素材可以使用平台生成图、自有图或 CC0 图，但必须本地化/稳定托管并记录来源。禁止把随机远程图片 URL 当作正式依赖。

### 15. 状态与错误体验

所有异步页面至少具备：loading、empty、success、error、retry 五种状态。

必须特别处理：

- 无网络、请求超时、5xx、429。
- 空间不存在、邀请链接格式错误、空间已关闭、照片已满 90 张。
- 文件为空、格式不支持、HEIC、超限、无法解码、全景比例错误。
- 对象已存在 409、数据库重复 23505。
- WebGL 不支持、纹理加载失败、首次渲染失败、context lost。
- 用户在上传中离页或连续双击。
- IndexedDB 不可用。

错误文案要说明“发生了什么、用户下一步能做什么”，不要只显示 `Something went wrong`。

### 16. 可访问性与响应式

- 使用语义化 `button`、`a`、`form`、`label`、`nav`、`main`。
- 每个输入有可见 label；每个图标按钮有 aria-label。
- Tab 支持键盘和 `aria-current/aria-selected`。
- Toast 使用 `role=status`，错误区使用 `role=alert`。
- 灯箱可用 Escape 关闭并锁定背景滚动。
- 手机、平板、桌面都不能横向溢出。
- 兼容 iOS Safari 的 safe-area 与 `100dvh`。
- 图片使用合适的 `loading=lazy`，但首屏封面不要延迟到空白。

### 17. 明确禁止的偷工减料

以下都视为未完成：

- 只有首页，没有完整创建、上传、查看闭环。
- 所有按钮都用 alert 或 console.log。
- 用固定假数据声称“上传成功”，但刷新后数据消失。
- 把 20–50 MB 全景转 Base64 存数据库或传给 AI。
- 上传重试时重新生成 ID，导致重复照片。
- WebGL canvas 一加载就盖住 2D，失败后黑屏。
- 用登录页或私密开关虚构权限。
- 把拍摄/拼接入口重新放回正式产品。
- 演示卡片不可点击，或者只展开文字而没有独立页面。
- 使用失效外链图片、无来源受限素材或前端硬编码 secret。
- 为了桌面展示套一个假手机外框。

### 18. 推荐开发顺序

按以下顺序实施并每步保持应用可运行：

1. 建立设计 token、AppShell、路由和响应式基础。
2. 完成首页、空间列表、创建、加入和空间详情静态交互。
3. 建立 Space/Photo 数据模型、对象存储和服务端上传票据。
4. 打通创建共享空间和本机草稿。
5. 打通 1/3/9 张普通照片上传、状态队列和失败重试。
6. 完成时间线、分享链接和跨浏览器加入。
7. 完成成品全景校验、2D 查看和安全 360° 增强。
8. 完成演示中心、理想成品和六幕故事。
9. 完成 15 入口 AI 档案馆。
10. 补齐错误状态、无障碍、自动测试与部署说明。

不要在已有数据结构稳定后进行无关重构。

### 19. 最终验收标准

交付前逐项自测并报告结果。

#### 视觉/路由

- 320、390、430、768、1440 宽度无白屏、无横向溢出。
- 430px 和桌面根字号均为 16px。
- 正式核心流程桌面为居中 430px 内容壳，无假手机边框。
- 首页四个场景可切换并正确预填创建页。
- 所有正式路由、演示路由和返回链可达；旧死路由自动回首页。

#### 创建/加入

- 无素材、有封面、有全景、封面+全景四种创建路径可用。
- 任一已选素材上传失败时，不发布空间；重试不重复创建。
- HEIC、未知格式、0 字节、超限、非 2:1、过小或过大全景在上传前阻断。
- 全景原文件不压缩、不转 Base64。
- 本机草稿刷新页面后仍存在。
- 邀请链接在另一个浏览器会话能打开同一空间。

#### 普通照片

- 1、3、9 张均成功；选择超过剩余名额时只接收可用数量并提示。
- 连续双击只发起一轮。
- 上传中不能添加、删除、重复提交或离开。
- 部分失败后只重试失败项，done 项请求数不增加。
- 409/duplicate 使用原 clientUploadId 恢复成功，不产生重复 Photo。
- 返回空间后时间线刷新且排序正确。

#### 全景

- 2D 图片永远先可见，支持拖动和缩放。
- 用户不点击时不加载 Three.js/WebGL。
- 强制模拟初始化失败、render 异常和 context lost，均自动回 2D、显示提示且无控制台未捕获异常。
- 反复开关 360 和切换路由无 RAF、事件或 WebGL 资源泄漏。
- AI 四幕 2D 左右连续拖动不露黑边。

#### 演示

- 演示中心四个入口都进入独立页面。
- 六幕可从 1 完整翻到 6，并进入理想成品。
- 理想成品四个 Tab 都有真实切换与内容更新。
- 档案馆 15 个入口全部可点击、可返回、无破图。
- 演示流程不写正式数据库、不上传 Storage、不调用相机。

#### 工程质量

- TypeScript、lint、build、测试命令全部真实通过，不能用 echo/no-op 冒充。
- 浏览器控制台没有新增 error。
- README 写清本地启动、环境变量、数据库迁移、部署和测试步骤。
- 最终报告只需包含：已完成页面、数据/上传实现、测试结果、仍使用 mock 的部分、真实限制和部署地址。

### 20. 完成标准

只有同时满足以下条件才算完成：

1. 正式产品从“创建/加入”到“上传照片”再到“查看时间线/全景/分享”形成真实闭环。
2. 演示内容完整但与正式数据隔离，概念能力有明确披露。
3. 失败和重试不会重复数据、不会黑屏、不会假成功。
4. 移动端好用，桌面端也不是被放大的手机截图。
5. 所有按钮都有真实行为，所有页面都有返回路径。

现在开始直接实现，不要只复述需求。先完成 P0 闭环，再完成全部 P1 演示，最后运行验收并修复失败项。
