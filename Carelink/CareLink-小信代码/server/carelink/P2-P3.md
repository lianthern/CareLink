# P2 free scope + P3 — 2026-10-31

Local implementation only. No production routes, cloud resources, deployment, APK signing or installation. P4 has not started.

## Device switch and rollback

`unseen-carelink-device` in device-local storage defaults to absent/disabled. For a **test device and test family only**, set `{ "enabled": true, "device": "single" }`, then reload the OS page. Dual devices use `device: "dual"`, `listenKey: "green"`, `speakKey: "red"` (configurable names). Remove that setting or set `enabled: false` and reload to return to the existing frame page. A query string cannot enable it. This round did not enable any real family or device.

The OS selects `../carelink/frame.html` only when enabled. Existing pairing, family calling, settings and native Y1 long press remain in the OS. Enabled AI entries route to CareLink; disabled handlers are untouched. Single native AI press is passed to the P1 state machine as a completed short press, because Y1Key already resolves the physical edges/800 ms long press. The dual native back/AI semantics map to listen/speak; raw key names and touch buttons use the same P1 machine. The 30-second recorder limit uses P1 ticks. Rules/keys browser files are generated from P1 sources, not rewritten copies.

## Photos

`photo-storage.js` defines prepare / complete / read. The local fake additionally exposes put / get, enforces SHA-256 and length, private grants with expiry, per-room paths and stable IDs. It is memory-only and intentionally test-only. COS construction does not load an SDK, credentials or environment variables. All calls reject `COS_APPROVAL_REQUIRED` by default; after an explicit future approval an injected private-object client must implement `preparePrivateUpload`, `headPrivateObject`, `signPrivateRead`. No public ACL or resource provisioning is implemented.

`CareLinkPhotoUpload.createDirect(adapter)` sequences prepare → put → complete. Only complete ACK permits success. The phone uploader uses an optional `window.CareLinkDirectPhotoUpload` callback; absent means the unchanged Hong Kong upload path. A rejected, malformed or timed-out direct upload always attempts Hong Kong with the same persisted file and ID. Both paths failing keeps the IndexedDB file and unsent message; message ACK still controls `sent`. A late direct success can leave an unreferenced object; the eventual COS integration must use idempotent IDs and server-side orphan expiry, not duplicate message creation. No live COS handler is wired.

The deferred phone compression code/test was transplanted at function granularity. `live-web/r15/r7-service.js` and baseline `chooseFiles` are identical (receipt in evidence). Existing 697 service fixes were retained. One addition scales large-dimension files even below 1.2 MB. Compression errors retain the original when the legacy limit permits it; oversized files that cannot be decoded still produce the inherited explicit error. File selection and the existing Hong Kong API keep their existing 3 MB upload constraint. No new five-tab phone UI, caching rollout or server configuration was added.

## New voice / health data

The new frame stores recordings as WAV blobs in scoped IndexedDB **before** a send attempt. No new recording, health or medication data is sent to `/api` or Hong Kong. `/api` is read-only legacy photo state; new photo events/cache are persisted and do not change the displayed photo. Images and attached original voice are cached locally when fetch succeeds. Incomplete caching is not represented as offline availability. The original account/backend storage partition still applies in the installed native client.

The optional **same-origin parent** `CareLinkTransport` is a future domestic-service seam:

- `region`: only `ap-shanghai` or `local-test-only` accepted.
- `photos()` optional: legacy-shaped `{messages: [...]}` for isolated tests. Otherwise old photo `state` API is read.
- `pending()` optional: array of `{id,type:'reminder',slot,plans:[{voiceRef,reminderText}]}`. Adapter must supply only reviewed active P1 reminders (not child analysis). New photos use `{id,type:'photo',imageURL,audioRef,createdAt}`. Persisted IDs deduplicate. Same-slot reminders chime once.
- `sendVoice({id,room,audio,createdAt,urgent,context})`: must resolve `{id,accepted:true,elderReply?}` **after domestic durable acceptance**. Implement ASR → P1 `process` → domestic storage/outbox there, retaining the stable id. `elderReply` must come from P1's elder branch. Browser also applies the P1 reply guard. ACK means service accepted, never family received/read.

Without a domestic adapter, audio remains queued, including while the old photo service is reachable. Retry order follows P1 urgent priority. Raw offline audio cannot be classified urgent before ASR; real immediate notification, real ASR/LLM/TTS, per-household billing limits, phone notification channel and domestic hosting are not wired or verified in this free slice. No emergency delivery claim is shown.

## Asset parity and verification

Both complete r15 trees are now byte-identical, including eight files that existed only in the native baseline. Native transpiled assets were used to preserve 697 fixes. Root `compat` assets were also made available to the server. A static ES2015 module loader preserves the old desktop TRTC SDK import URL while WebView keeps its compiled loader/native RTC path; the previously passing RTC test failed during the initial mirror sync and passed again after this correction.

Commands/evidence and limitations are in the external plan `PROGRESS.md` and repository `evidence/p23/`. Android validation used the already installed **Frame 696 test variant**, HTTP interception to local current assets, and WebView 66; it does not prove a new APK install or validate 697 native changes. No new APK was built or signed. Real microphone PCM capture and keyevent 231 ran; synthetic playback was held by a test promise for the label screenshot, so audible native TTS is not claimed. The chime implementation is Web Audio and the “light” is a screen border; a physical LED and real speaker loudness are unverified.
